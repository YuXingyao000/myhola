# 单机八卡条件下的 PBR 配对图像基线

最新需求入口：[布景模板生成协议 v0](codex_scene_factory/TEMPLATE_CONTRACT_V0.md)，实现组织见 [代码方案](codex_scene_factory/CODE_LAYOUT.md)。制作目标是跨 CAD 复用的模板及程序材质；模型制作阶段输入占用包络与三项创作需求，具体 STEP 留到批量拍摄。用户已确认拍摄预设为归一化原点目标、相机 `(2,2,2)→原点`、`512×512`、FOV `45°`。支撑高度由外围固定程序通过模板实例化匹配当前 CAD 最低点，CAD／相机保持不动；以下较早通用方案以该协议为当前优先入口。

## Task

为单图到 B-Rep 研究建立可扩展的合成真实感图片基线：**已知 CAD → 受控工业材质与三维场景 → Blender Cycles → 有限相机成像处理 → 审计与打包**。几何和投影由 CAD／相机决定，外观变化来自材质、照明、环境与成像。这是几何可靠性优先的传统物理渲染基线，不是已经证明优于生成式合成的最终方案。

状态：2026-10-12 的设计提案，尚未实现、测速或验证真实感；本轮不启动生成、安装依赖、下载资产或训练。逐图付费 API 调用数为 0，主线逐图 diffusion 调用数为 0。场景程序的制作可以使用有预算的 Codex 调用，冻结后的图片生产不依赖逐图 agent 决策。

上层工程见 [Codex 场景程序生成与 CAD 配对渲染工程](codex_scene_factory/PLAN.md)：由版本化规格驱动 Codex 自动制作、预览和有限修复场景，再由独立渲染器注入已知 CAD 批量生产。本文件保留物理渲染、材质和场景制作的内容要求；三个场景族是启动样例，不限制场景程序库的规模。

当前最小摸索接口见 [场景协议 v0 草案](codex_scene_factory/SCENE_CONTRACT_V0.md)。输入按 STEP、明确相机和可补全场景提示组织；STEP 转网格、相机规范化、灰模参考与入画检查均在调用模型前完成。用户已明确首版目标零件按刚制作完成的外观处理，仅用数值／程序函数驱动 PBR，不用图片贴图；场景表面仍可使用已登记资产。先协议化支撑表面、目标空间及场景交付，不要求完整调度系统先落地。

后续由可程序调用的 Codex 作者完成 Blender Python 场景搭建与材质提议，独立控制器负责验证、预算、冻结和批量生产；用户不需要手工维护 Blender 节点。旧代码、旧相机编号和旧 loader 仅是迁移背景，不约束基线设计。

研究假设是：将生成自由度限制在受控材质与场景中，能减少配对标签破坏，并以可接受的真实感和单位可用图成本扩库。PBR 的实拍域差距是待验证风险，不预设其真实感或下游效果优于 FLUX。

- 环境事实：当前 shell 的 `PATH` 未找到 `blender`，不能据此断言系统完全没有 Blender；实施时需定位或安装并固定一个版本。本轮不安装。
- 资产事实：DeepCAD v7 的示例对象有 `normalized_shape.step`、`mesh.ply` 和 `data.npz`；本地 FLUX base model 和 Q8 GGUF 文件存在，但未验证推理环境。旧 SAM2 checkpoint 路径不存在。
- 清单事实：当前源清单包含 train 46,627、validation 3,505、test 2,424 个不同 ID。这些是清单计数，不是新图可用数量。
- 首版工作域建议：单个不透明机械零件、桌面／工作台／检验台场景，先覆盖金属与涂层外观。不把该范围宣称为全部真实照片分布；透明件、严重遮挡、手持交互暂不进入第一版。
- 当前用户明确的摆放需求：单个 CAD 保持给定旋转，沿支撑平面法向平移到接触；允许尖点支撑及重心偏移，不以力学稳定性过滤。刚体模拟／重心判断留给后续独立过滤。相机是独立配置，外观摸索时建议固定，未来再扩展连续视角；显式保存 CAD 到世界再到相机的变换及内参。旧 identity／cube24 编号不构成限制；不得用旧编号代替实际变换。
- `Needs confirmation`：目标实拍中材质和背景的实际比例、源 CAD 的物理单位、可用于校准的同域实拍参考。当前可使用均衡覆盖设计，但不能把它当作实拍分布估计。
- 所有图片称为合成真实感图片；最终实拍泛化需要独立下游评估。

## Inputs

1. 冻结的 CAD identity／去重组与源 train／validation／test 清单，以及源 CAD、`data.npz` 和版本摘要。
2. 已知几何与相机：优先从 STEP 重新三角化并保留 `face_id`、曲面类型、正确朝向与法线；核对三角化误差。不得以平滑、倒角、补洞或缩放猜测静默改变目标几何。
3. 可复用材质注册表：材质族、参数范围、程序函数坐标框架、微表面尺度、加工方向、版本。初版目标零件不使用图片贴图或 UV atlas，按刚制作完成的外观处理；不加入锈蚀、污渍或宏观磨损。
4. 可复用场景注册表：台面／墙体／稀疏道具、光源、环境贴图、支撑方式与允许的参数组合。资产来源及文件摘要单独记录。
5. 少量免费可下载的环境与表面资产。场景制作阶段建议整理 6–8 个室内／摄影环境 HDRI、8–12 套台面／墙面／包装 PBR 表面资产，以及 5–10 个简单背景道具；道具优先程序化搭建。这是候选资产准备规模，不是已下载数量或覆盖率证明，不据此断言全机没有可复用资产。后续按重复与覆盖审计扩充。
6. 冻结的采样规则与随机种子：`sample_id = CAD identity + view_id + appearance_id`；`appearance_id` 包含外观配方与重复编号，例如 `cfg03_rep01`。每配置两个 seed 对应两个不同 appearance ID，各阶段 seed 由 ID 与版本确定性派生，不能依赖 worker 排序或跳过样本后的 RNG 状态。

## Outputs

生成资产与旧条件根目录隔离，已有图像和 latent 不覆盖。

| 输出 | 建议合同 |
|---|---|
| RGB 主图 | 按 `model_id/view_id/appearance_id` 保存 1024×1024 RGB uint8 PNG；训练派生图为 512×512，并检查实际 224 输入下的结构可辨性 |
| 几何参考 | 每个 CAD／相机缓存一次无纹理参考图与前景 mask；mask 为 uint8，背景 0、前景 255，孔内背景不填实 |
| 审计用 G-buffer | 固定审计集保存 camera-z depth float32、camera-space normal float16、face ID uint32；背景统一为 0，face ID 为本地面号加 1，坐标和单位明确写入元数据 |
| 每次请求记录 | 源 CAD／mesh 摘要、源 split、相机内外参、物体变换、归一化、假设物理尺度、材质／场景／灯光配置、seed、软件版本、实际 GPU 后端、耗时和状态 |
| 阶段状态 | `requested`、`render_failed`、`technical_ok`、`visual_accepted`、`visual_rejected`、`unreviewed` 等分开；技术检查通过不等于真实感通过 |
| 结果记录 | 完整请求清单、失败原因、首次产出率、人工审查结果、分层覆盖与成本报告 |

全量默认保存 RGB、可复用 mask 和元数据；depth／normal／face ID 优先保留在审计集，其他样本按配置可复现重建。避免将多个 float 通道无目的复制到所有外观变体。图像、二进制缓存放在独立数据根或被忽略的运行目录；紧凑报告留在本主题目录。

新基线以显式 manifest 为数据合同，分别记录 CAD、相机、姿态与 appearance，来源为 `generator=cycles_pbr`。训练消费接口在后续实施时适配，不为沿用旧 loader 限制相机或外观设计。旧 `real_photo.npz['flux']` 如需导出，作为单独版本的迁移产物核对；appearance 不能塞进旧 `[24,H,W,3]` 旋转维度，任意新姿态也不能冒充旧 `_0` latent。

## Processing Protocol

### 0. 当前需求拆分（2026-10-12 用户补充）

当前是需求摸索，不冻结大型生产 campaign，也不将下面的材质候选当作已经确定的真实照片分布。每个场景实例先按六部分表达：

| 部分 | 当前最小需求 | 主要可变项 |
|---|---|---|
| CAD 与摆放 | 源几何、固定旋转、平面接触；不要求重心稳定 | 初期不改姿态；尺寸假设与平移显式记录 |
| 零件材质 | 一个受控 PBR 材质配方，整体一致为起点 | 材质族、颜色／反射、粗糙度、微观纹理尺度与方向 |
| 支撑表面 | 一块足够大的桌面／地面 | 表面材质、颜色、尺度、有限使用痕迹 |
| 周围环境 | 墙面／开放空间及少量背景物体 | 空间布局、道具距离、背景复杂度、反射内容 |
| 照明 | 明确的主光与环境照明方案 | 方向、光源尺寸、强度、颜色、明暗对比 |
| 相机与成像 | 记录相机内外参及颜色管理，摸索时先固定 | 后续再扩展视角、焦距／距离、曝光、白平衡与轻微成像变化 |

环境与照明分开配置但协同制作：墙、桌、窗及相机外物体可以改变金属中的反射和间接光，不只是背景像素。只更换零件材质而不检查反射环境，不能定位“塑料感／CG 感”的原因。镜头与相机改变投影，不混入普通外观随机项。

材质配方不要求每个属性都有贴图。常数或程序函数同样可以提供 base color、roughness、metallic；normal／bump 是可选微表面细节，AO 不是必备材质通道，目标真实 displacement 仍禁用。常见贴图名 `diffuse` 是漫反射颜色，不是 `diffusion` 生成模型。金属度工作流下的 base color 同时涉及金属反射颜色，不能把所有材料都当作漫反射表面。

材质探索按独立资产任务组织：

1. **当前确定的基线**：目标零件只用数值／程序函数控制 PBR，呈现刚制作完成的外观，不用图片贴图。初始考虑喷砂金属、机加工金属、不透明喷漆；哑光塑料作为可扩展候选。材质族内部相关采样，不把方案限制为固定八种外观。背景／支撑面的可靠表面资产仍可使用，此限制不扩展到整个场景。
2. **暂缓的生成式探索**：以后若需求明确，可离线生成可平铺的成套 PBR 材料，检查通道对应、换光响应、尺度、重复接缝和可疑假结构后入库；一套材料供多个 CAD 使用。材料生成不要求提前知道目标 CAD 的 UV。StableMaterials／MatFuse 是相关方法实例，不代表已选定、部署或验证其权重许可、速度和质量，也不训练新模型。
3. **需求出现后再考虑**：特定 CAD 的局部磨损、喷漆边界、文字或加工方向，需要形状条件、表面区域／方向或 UV／多视图对应。UV 可在三角化后计算；B-Rep 曲面的局部参数域不自动等于连续、低畸变的纹理 atlas。自动展开只解决映射的一部分，不自动解决接缝、生成通道一致性或结构幻觉。

无 UV 的首版映射：三维程序纹理按物体局部长度坐标取值；二维可平铺颜色／粗糙度／标量高度通过平面、圆柱或三向投射使用。normal 向量不能当普通 RGB 用三向混合后直接接切线空间 Normal Map；需要各投影坐标系的法线转换与正确混合。首版可先使用程序标量高度驱动受限 bump。拉丝／车削反射还需要明确切线方向，复杂曲面方向场作为独立问题。

普通生成式 RGB 可能已经包含高光、阴影和假凹凸，不能直接命名为 albedo，也不能用一次灰度转换假定获得正确 roughness／height。生成材料是否优于扫描或程序材质，在同 CAD、同相机与同照明下比较，另做换光检查，不用单张最佳渲染决定。

### 1. 重建正确的灰模输入与几何缓存

从已知 CAD 得到受控三角化、正确的面方向、连续曲面的法线和真实硬边。保留原 B-Rep 标签，禁止为好看而加几何倒角、额外孔槽、螺钉、位移或透明裁剪。输出灰模、mask 与审计 passes，核对源 CAD 到渲染器的变换。

每个样本先确定相机与姿态，再生成外观。当前保留输入旋转与平面内位置；若相机已经给定，推荐对 CAD 与相机共同沿 Z 平移，使最低点落在内部 `z=0` 支撑面而保持相对投影。若绝对世界坐标被锁定，则维持 CAD／相机不动，将支撑面放在最低点高度；不能仅平移 CAD 后声称保留原构图。保存坐标变换，检查接触落在有限支撑面内、没有穿插。允许点／边接触，不执行刚体沉降，不按重心是否位于支撑区域过滤；`stability_status=not_evaluated`，不把未经计算的摆放标为稳定或不稳定。相机记录焦距／内参、距离、观察方向及画面占比，规范化之后的外观对照固定相机。不得依赖旧编号推断对应。同步保存 canonical CAD 到渲染坐标的变换，后续训练若使用旋转 latent，按新合同生成或适配。支撑物不得穿入零件或遮住关键结构；有限台面不兼容等几何问题显式记录，不以力学不稳定为由拒绝当前请求。后续物理过滤单独版本化，保留原图与清单。

归一化 CAD 若缺少物理单位，渲染用物理尺寸必须作为显式假设采样并保存；该尺寸不是源 CAD 的测量真值。它通过明确的渲染单位换算／统一场景缩放实现，同步变换相机位置与几何，保持二者相对投影；不能只缩放零件再沿用原相机。canonical CAD／latent 坐标不变，渲染单位到 canonical 坐标的变换单独记录。纹理长度、场景尺度和灯光参数按所用单位明确设置。

### 2. 建立少量受控的工业材质族

初版建议三类，优先做对而非扩大不受控贴图数量：

- 干净机加工／拉丝金属：连贯的粗糙度和方向性反射，微细加工痕迹主要作用于 roughness 与受限法线。
- 喷砂／哑光金属：细尺度的粗糙度变化与弱微表面起伏，不叠加大块石材般噪声。
- 涂层／喷漆表面：使用合理的涂层响应、颜色和细微表面差异，避免把涂层简单当作任意金属度插值。

参数在材质族内部相关采样，不将 metallic、roughness、颜色、划痕强度分别独立乱采。材质分配不与 CAD identity 或 split 形成固定绑定；同一 CAD 的多个外观覆盖不同族和环境。

优先使用随物体运动的统一长度坐标和三维程序化标量纹理；不按各轴包围盒分别归一化纹理尺度。方向性加工痕迹可利用 CAD 平面／圆柱面的局部方向；复杂 UV atlas 不作为首版必备工程。若使用外部法线图，必须核对坐标框架及 OpenGL／DirectX 约定，不能把切线空间贴图直接当物体空间法线使用。

裸金属与不透明喷漆分别建材质配方：前者使用金属反射，后者以介电涂层表面响应为主，不能用任意 metallic 中间值模拟油漆。初期不根据 face ID 任意分配不同颜色，不给每个面制造装配分件暗示。程序纹理优先作用于粗糙度，避免大块颜色噪声变成石材外观。Bump／normal 同样限制强度；禁止用 Bevel shader 假造源 CAD 没有的边缘圆角。真实锐边保留，视觉不够好不能成为改标签的理由。

先在统一诊断场景里用灰卡、粗糙／光滑球和代表性零件检查曝光、反射、曲面法线与材质，再把同一材质带入三类生活环境。诊断物体只用于调试画面，不进入训练图。

初版不使用重锈蚀、宏观磨损、大幅 bump／normal 或外观图像中烘焙的假孔槽。微观纹理同样需要可见结构审查，固定 mesh 不代表外观绝不会误导。

### 3. 建立物体、背景与照明共同参与的场景

制作一个诊断场景与三个生产候选场景族，均使用真实三维近景。以下是设计选择，不是目标实拍类别比例的测量结论：

| 场景 | 具体空间与道具 | 照明设计 | 在基线中的作用 |
|---|---|---|---|
| `studio_diagnostic` | 中性台面／背景、可移动反光板，诊断时加入灰卡与材质球 | 大面积柔光，固定曝光与颜色管理 | 分离材质、法线和灯光问题；不作为主要训练背景 |
| `inspection_bench` | 灰色层压板或防静电垫、浅色墙面、远处收纳盒或柜体 | 窗口侧光或顶部面板灯，两种预设分别制作 | 普通清洁室内零件照片，优先完成第一套场景 |
| `workshop_bench` | 工作台、有限使用痕迹、工具板／架子；工具留在后景 | 大面顶灯，匹配的室内环境反射；控制对比 | 避免数据只有摄影棚和办公木桌 |
| `packing_table` | 纸板垫、收纳托盘、背景纸箱或隔板 | 柔和室内光或窗口光，近景接触保持明确 | 增加表面材质、色调、空间布局差异 |

先完整制作 `inspection_bench`：桌面提供实际支撑与纹理尺度，后墙和柜体提供空间及金属中的反射，窗口或顶灯定义主要光源，相机与道具按明确位置放置。先让一个可复现场景整体成立，再把它参数化。无须建完整工厂或大量相机看不到且不贡献反射／遮挡的高精度资产。

每个生产场景族计划提供 3 套空间布局、2–3 套合理照明预设和若干表面组合。它们是制作目标，不是已完成资产或等价于独立实拍场景的数量。采样先选场景族，再选允许的布局／光照／表面组合，最后改变物体摆放、相机和轻微成像参数。禁止把所有属性独立笛卡尔积随机混合；初始均衡覆盖用于发现问题，后续用实拍开发参考调整分布。

HDRI 用于环境照明与远处反射；桌面、支撑、近墙与邻近道具由实际三维几何提供透视、接触和遮挡。不能把任何 HDRI 与任意桌面拼接后视为物理一致。明确每套预设由环境光主导还是显式灯光主导，避免重复加入已在 HDRI 中的强窗光导致双重高光／阴影。可见窗、显式面积灯与主要入射方向保持对应。封闭房间不能指望世界 HDRI 穿墙照亮内部，需安排开口或实际室内灯；环境的亮度、白平衡和旋转均记录。

零件与台面必须接触且无穿插。桌面纹理使用其物理重复尺度，不随 CAD 包围盒拉伸；只有明确的尺度假设才能调整零件尺寸。小道具不与零件接触，在图像上保留分离，避免独立工具或螺钉被理解为目标结构。初期不通过强景深把所有背景糊掉，也不靠强 AO 黑边、重污渍或锈蚀制造真实感。适度真实的微小差异可以加入，但不能掩盖孔槽。

背景模板需要检查接触、尺度、透视与反射关系。仅改变 HDRI 旋转或木纹颜色不算新增场景类别；不同 CAD 的形状变化也不能计入背景多样性。背景近重复和场景覆盖在批次层面独立报告。

资产准备按用途分工：HDRI 与台面／墙面扫描材质优先选择免费 CC0 资源；托盘、纸箱、柜体等简单道具程序化建模即可，复杂工具只在必要时引入。记录来源页、许可、文件摘要、物理尺度、颜色空间、法线约定及允许使用的场景。启动时优先 2K／4K 表面材质与适合反射用途的环境图，不默认全库 8K。素材清单和质量比素材总数重要。

### 4. 批量渲染与成像

固定 Blender 版本与 Cycles 后端。建议以 1024 分辨率、64 samples 作为启动配置，使用自适应采样；最高采样数与去噪设置在审计集校准后冻结。该配置是起点，不是质量／耗时保证。检查去噪前后是否抹掉细孔、薄壁或局部加工细节；高光难例不能用任意光线截断静默处理。

固定颜色管理与视图变换（可从 AgX 起步），在诊断场景校准曝光后限制生产扰动范围。颜色贴图按其颜色空间加载，粗糙度／金属度等数据贴图按 Non-Color 解释。灯具尺寸与距离共同控制高光和阴影，不能只调强度。所有设置随版本存档，禁止逐图人工修到好看后隐去制作成本。

首版只允许受控曝光、白平衡、轻度噪声与压缩等成像变化。相机裁切、镜头畸变、任意几何 warp、强景深暂不作为普通外观增强；将来使用必须同步投影标签并检查可辨性。

保留一个未加成像扰动的审计版本。无需逐图运行 SAM2、DINO、CLIP、LLM 或 diffusion。

### 5. 审查、版本化与打包

全量检查 ID／split／变换／配置／状态、输出可读性、尺寸和数值范围；抽样检查视觉真实感与可见结构。出现错误 CAD、视角错配或静默几何变化，停止该版本扩库。

没有人工或已校准视觉判据的样本保持 `unreviewed`；不能把 `technical_ok` 数量叫作逐张认证的真实感合格数。批次级抽样验收与逐图标签分开报告。

### 6. FLUX 的定位

本地 FLUX 是有限预算的竞争工作流，不是逐图必经后处理。可在冻结子集上用相同 CAD／相机／目标外观请求做对照；所有首次结果保留，不能只留最佳 seed。

若后续证据显示必须依赖生成模型补充背景或细节，优先研究一次性生成可复用资产，或在明确区域内处理并重新渲染物体。生成 RGB 不能直接冒充无光照 albedo 或 HDRI。对源物体重新生成 RGB 会重新引入结构风险，不因使用 mask 而豁免审查。

## Metrics

1. **协议完整与正确性**：全部请求的溯源完整率、相机／变换一致性、错误 CAD／跨 split 混入计数、显式几何改变计数。协议错误与图像质量失败分开。
2. **可见结构可信度**：在固定相机参考下标注轮廓、孔槽、柱、薄壁、厚度／比例的误导；将几何改画、反光／阴影造成不可辨认、测量失败分开。隐藏几何不从单张图片认证。
3. **感知真实感**：隐去方法名，先评价物体材质、背景、接触／反射／照明关系及整图，再展示 CAD 参考检查结构。混入同域实拍参考，统一展示尺寸；VLM 仅辅助，不替代独立真值。
4. **有效覆盖**：分别统计 CAD／结构类别、材质族、场景模板、环境及其组合的请求数、技术成功数和审查结果；背景近重复应在排除前景影响后分析。不同 CAD 不能掩盖背景重复。
5. **可靠性与成本**：首次联合可用率、每 CAD 跨 seed／配置的失败情况、所有 GPU 秒／审查合格图、端到端耗时和存储。失败、重试和超时均计入成本与预定分母。未审查样本不混入人工通过率分母。
6. **下游价值**：后续以相同 CAD 数量、训练曝光与推理预算比较旧／新数据，在独立实拍上报告有效 solid、可见一致性和可用 GT 下的几何误差。当前阶段不以渲染成功或 diffusion loss 推断实拍收益。

渲染器的 G-buffer 是已知场景标签，不是独立真实感评价；不得用同一源 mask 的一致性自证生成质量。没有同场景实拍 RGB 时，不能将 PSNR／SSIM 或与灰模的像素相似度当照片质量。

## Decision Rule

- 先用开发子集校准标注规则和自动诊断，再冻结验收子集。技术／视觉阈值不得根据冻结集结果反复放宽。
- 协议完整率要求 100%；发现错误 CAD、旋转错配、跨 split 泄漏、静默改变几何即暂停该版本扩量并修复。
- 可复现的孔槽／薄壁视觉误导不得由整体均值掩盖。若失败集中在某类 CAD／材质／照明组合，应报告该适用边界，不能只删除难例抬分。
- 项目验收可将冻结审查子集“首次同时通过结构与外观判断达到 80%”作为待校准起点，并同时报告各结构类别和按 CAD 分组的不确定性；80% 是工程目标提案，不是文献认证标准。若实际参考和标注无法支持这个定义，先修订开发协议，不进入规模化。
- 若背景覆盖仍集中于单一模板或物体真实感持续不达标，不直接生产几十万张；先判断受限因素是材质／场景实现，还是纯 PBR 与目标实拍的域差距，再决定是否引入本地生成模型。
- 原始清单的覆盖、首次结果和单位可用图成本与质量并列。旧 FLUX 存档只用于诊断；缺乏完整生成协议时不把它当严格公平对照。

## Edge Cases

- 空清单、重复 sample ID、未知 view／appearance 定义：在分发任务前报错；不生成看似成功的空报告。
- 缺 CAD、损坏文件、非法 mesh、缺材质／场景资产、NaN／Inf：记录 ID 和具体失败阶段，禁止静默换 CAD、材质或路径。
- 固定姿态不能与有限平面正确接触或场景穿插：标记 `support_contact_invalid`／`scene_collision`，不自动改变旋转、相机或几何；保留在覆盖统计里。力学不稳定不属于当前失败条件，稳定性尚未计算时保持 `not_evaluated`。
- 极小孔槽／薄壁在 512 或实际 224 输入中不可辨：标记尺度与可辨性问题，不当作生成器凭空删结构。高分辨率正确不意味着训练输入仍保留证据。
- 高反光、近黑材质与低对比场景：区分物理合理但信息不足、渲染数值失败、外观不合理；不能由简单亮度阈值统一清洗。
- 去噪或成像处理损害细节：版本化记录处理链，与原始渲染并列审查；不能只保留美化后图片。
- GPU OOM／进程崩溃／超时：按固定技术重试策略记录；不得暗中降分辨率或换 CPU 并维持同一协议标签。视觉拒收不自动无限重抽。
- 预定分母大于零但全部失败时，成功率为 0；分母为零的比例才为 null。无人审查时人工通过率为 null，技术成功率另算；保存分子分母，不能将未审查样本假定为通过。
- 已存在输出：只有输入摘要、配置、代码和状态一致才复用；否则新版本目录，不能只凭文件存在跳过。

## Validation / Sanity Checks

实施时先完成可评审的场景制作，再进入有限试产。制作顺序为：诊断场景与三类材质 → 第一套检测台 → 车间／包装两类场景 → 参数化和随机化。每一步用包含孔槽、薄壁、细柱与曲面的固定代表性零件，交付同视角比较图、完整场景视图、局部细节与可复现 `.blend`／脚本。这是检查基线是否正确实现，不代替后续研究效果评估。

第一轮场景评审同时提供“同零件换材质”“同材质换场景”和“同场景换种子”的对照，便于分别判断材质真实感、场景一致性和变化是否有效。保留不理想结果及原因；场景制作时间与后续逐图成本分别记录。随后使用以下有限试产协议：

| 阶段 | 建议规模与停止预算 | 要回答的问题 |
|---|---|---|
| PBR 方向验证 | 96 CAD × 4 外观配置 × 2 seeds＝768 请求；最多 24 GPU 小时 | 三类材质与多场景是否可保持可见结构并达到照片外观要求 |
| 划分与审查 | 32 CAD 开发、64 CAD 冻结；覆盖孔槽、薄壁、曲面、凹结构及简单形体 | 指标能否发现结构误导、材质异常、背景重复和接触错误 |
| 可选本地 FLUX 对照 | 冻结集中的 32 CAD × 2 外观要求 × 2 seeds＝128 首次请求；最多 16 GPU 小时 | 同一任务要求下，PBR 与整图编辑的真实感／结构／成本取舍 |
| 扩量前稳定性阶段 | 通过前述判据后，建议 2,000 CAD × 4 外观＝8,000 请求；最多 128 GPU 小时 | 较广 CAD 覆盖下是否出现系统性失败与资源瓶颈 |

GPU 小时是停止上限，不是预计耗时；达到预算后未完成项仍保留状态。人工审查采用预先固定的分层子集和盲评顺序，不能假设已有额外付费标注人员；可先预留约 2 小时用户审阅，根据实际审阅速度预先限定数量。单人审查属于开发判断，不宣称双人独立基准或精确全库错误率。

验证内容包括：CAD→mesh→相机的独立坐标核对、已知孔槽／薄壁案例、正确法线与纹理尺度、变换后图像与标签的一致性、去噪前后细节、同 seed 重建与跨 worker 重排的一致性、失败状态留存、旧资产未覆盖。无需对整个仓库或全部历史实验运行测试。

## Implementation Constraints

- 核心使用 Python、Blender/Cycles、现有 CAD／数组工具；不训练新的图像生成模型，不引入付费逐图 LLM/VLM 服务。
- 第一版采用 8 个常驻 Blender worker，每个只使用一张 GPU。CPU 几何预处理、GPU 渲染、CPU 打包分阶段队列；限制各 worker 的 CPU 线程与写盘并发。同一 CAD 的多个外观连续处理以复用网格和加速结构。
- 实际验证 OptiX 后优先使用；若需 CUDA，显式记录后端并单独测量，避免同时让每个进程占用全部 GPU。批量生产与训练分时安排，不能把整机同时承诺给两项任务。
- 配置版本化、每请求确定性 seed、原子写入与可追溯恢复；随机数复现不等于跨 GPU／软件版本逐位相同，渲染容差与版本一并记录。
- 新建清晰的资产注册、材质构建、场景构建、相机／摆放、渲染和数据记录边界，配置与 `.blend` 场景均可审阅。旧实现仅在符合新合同后选择复用，不把修复旧 Hydra／CLI／NPZ 入口设为场景基线的前置条件。
- 首轮优先扩独立 CAD 覆盖，之后给每 CAD 4 个受控外观；不默认展开全部 24 视图。若在现 train 清单每件生成 4 张，则是 186,508 张训练图，但这仅是计数规划，不是自动启动的任务。
- 对吞吐量只做条件估算：`wall_seconds ≈ N × measured_seconds_per_image / (num_gpus × utilization)`，准备／打包阶段另计。以 20 万图、8 卡、75% 有效利用率为例，单卡每图 5／20／60 秒分别约为 46／185／556 小时；这些秒数是假设，未测量。接受率小于 1 时每张可用图成本更高。
