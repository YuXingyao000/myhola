# Step 4：场景真实质感增强

## Task

建立普通 Python 可批量执行的图像增强阶段。输入 Step 3 的 RGB 与零件 mask，
从原渲染图进行有掩码的低强度生成式增强。八个场景各固定一份英文提示词，
不对每个 CAD 调用 LLM。交付修正支撑面后的原 100 件办公室样本增强结果与比较图。

## Assumptions

输入输出均为 512×512；“4K”仅指照片质感目标。当前先增强环境，原零件像素保护。
原生 512 的 Kontext 摄影化效果弱，明确蓝桌面阳性对照成功，已排除编辑通路失效。
允许另外对照内部 1024（该模型推荐尺寸），最后缩回 512 并在原尺寸合成；
内部尺寸显式记录，不将其描述为原生 512 的结果。
本批 100 件均属办公室；八份提示词不代表八个环境都已完成增强实验。
原 100 件只有 34 张旧支撑面图，不能作为正确输入；在独立目录重拍同一冻结清单。
用户已释放 GPU 7；只使用此卡，Blender 与增强顺序执行。

## Inputs

Step 3 request.json、renders.jsonl、逐件 rgb.png/mask.png/metadata.json；
八场景注册表及相应场景描述；本地模型及分词器；显式配置与 seed。
首选验证已有 FLUX.1 Kontext dev Q8 GGUF + FluxKontextInpaintPipeline；
若效果不足，再与摄影取向模型比较，不把本机可用性当作质量证明。

## Outputs

独立 run 目录保存冻结请求、源码、配置、提示词、模型身份/摘要、逐件记录、
原图引用、模型原始输出、最终合成图、保护 mask、编辑 mask、对照图和汇总。
保留全部预定样本及失败原因，完成度与人工质量结论分别记录。

## Processing Protocol

读取并核对 Step 3 → 冻结场景提示词和样本 → 一次加载模型并缓存提示词编码 →
逐件读取原图及掩码 → 扩张保护范围并仅在外侧羽化 → masked img2img →
合成回原始保护区域 → 检查尺寸/像素保护 → 保存结果与汇总。
先在修正后的固定五件上比较强度，再以固定配置运行原 100 件。
每次采样从原始渲染图开始，不将上次增强图递归增强。不自动无限重试或丢弃失败。

## Metrics

planned/success/failed/not_run；保护区域最大像素差；背景平均绝对变化；耗时与显存峰值。
人工对照检查纹理真实感、布局改变、接触阴影、轮廓接缝与反射协调。
背景变化大小只描述改动程度，不作为真实感分数。原深度不是编辑后背景几何的 GT。

## Decision Rule

技术通过要求输出尺寸正确且保护区域像素差为零，输入具备通过的支撑接触检查。
模型与强度依据固定样本对照选择；不以文件存在或数值变化宣称真实感提高。
保留未增强基线。最终人工验收状态不由技术检查替代。

## Edge Cases

空输入、重复 ID、尺寸不匹配、空/全白 mask、缺失源字段或文件在准备阶段报错。
逐件推理失败记入结果并继续，只有一层样本异常边界；模型加载失败直接退出。
损坏图片或非有限计算不计成功，未执行项仍留在预定分母。无背景时不能计算变化均值。
旧批次无有效支撑验收不得静默进入正式增强。输出目录不能覆盖旧 run。

## Validation / Sanity Checks

核对八场景 ID、提示词一对一；原 100 件列表/尺度/seed 与新渲染请求完全一致。
用含孔/细边的掩码验证保护区与羽化方向，验证最终保护像素精确相等。
真实 GPU 验证模型加载、512 原生输入输出、strength 对实际去噪步数的影响及批量复用。
对照实际图片审查，保留未通过样本。记录本地依赖版本与执行代码。

## Implementation Constraints

可读的 workflow.py 主流程；模型调用、掩码合成、提示词分文件。
提示词采用独立 .md，参数与场景映射采用 JSON；不引入 Agent 框架或 ComfyUI 服务依赖。
默认一张 GPU、逐图推理、模型常驻与提示词缓存；不修改训练环境，不混用其他 GPU。

## Deliverables

step4 代码与使用说明、八份场景提示词、五件强度对比、修正后的 100 件输入及增强结果、
验证报告与研究记录。结果命名为合成真实感图像，不能称为实拍照片。
