# 手机摄影质感：修图与 diffusion 并行比较

## Task
试自适应 3D LUT 修图，同时改进现有 diffusion 增强。目标是自然手机摄影的观感，
不是把“4K/iPhone”写进提示词就视为成功。全部输出仍是合成真实感图像。

## Assumptions
现有输入为显示映射后的 512×512 RGB PNG，不能当 RAW 或线性 EXR 再套 HDR 输入处理。
允许独立候选改变 CAD 光色以试验统一的摄影处理；原 RGB 锁定版与整图版明确分开。
整图生成不是结构保证，不直接进入训练集。两种路线均不改原始图片或相机/GT。

## Inputs
samples.json 固定六件：前五件来自已修正接触面的开发 pilot，最后一件来自 full100
的已知笔状道具失败例00320493。全部原 split 为 training，属于开发探索而非 test。
前五件沿用 seed8–12，最后一件 seed13；保留源数据/几何/相机/输入 SHA。
GPU7供 diffusion，其他卡不动；LUT仅CPU。已有 Kontext/Krea Q8 与官方 sRGB LUT 权重。

## Outputs
每轮独立目录：冻结代码、配置、提示词、输入/模型摘要、原生成图、原 CAD 回贴版、
全部六件比较图、耗时/显存/结构检查与人工审图记录。未执行、失败保留在分母。

## Processing Protocol
A：官方 paired/unpaired sRGB 自适应3DLUT，CPU推理，mix0.5/1.0（分支独立 PLAN）。
B：官方 FluxKontextPipeline 整图编辑，原图作为参考而非低噪声起点。
先 1024内部、28步、guidance2.5，统一手机照片风格指令，输出缩回512。
C：Krea masked img2img 内部1024、guidance2.5、strength0.25/0.35，40时间表步，
对比旧512低强度的材质改动与道具错误。已在运行前核对动态sigma shift：
512/.35与1024/.25初始sigma约0.503与0.513；1024/.35约0.630。
因此这不是单变量分辨率实验，实际sigma必须记录，不以同strength声称等噪声。此项与B依次占同一GPU，A并行。
每组先看前两张决定是否存在实现故障；完整六件保留，不根据美观挑图删样。
若整图生成改善色调却改结构，再研究只提取其光色映射，保留原图空间信息的组合。
新增方案应先补协议，不能把看结果后的方案伪装成预定比较。

## Metrics
覆盖率、实际steps/时间/显存、RGB差、明暗截断比例；保护版CAD像素差必须0。
整图版检查 CAD轮廓/孔槽/接触与背景物件是否漂移；边缘指标仅提示，不作几何证明。
视觉维度：曝光/白平衡自然、材质反光/纹理可信、非绘画/塑料感、局部清晰度、
道具结构与接触阴影。颜色变化或技术pass均不等于真实感提高。

## Decision Rule
先判结构与道具错误，再比较摄影质感；明显新形状/孔槽变化的整图候选不能入库。
摄影处理允许调色但应保留可辨内部边界；LUT没有坐标重采样不等于可见信息无损。
六件全部审图，最终展示收益与失败；未达到手机照片观感如实记未达到，不扩大100件。

## Edge Cases
无效输入/缺文件在准备阶段报错；非有限输出失败；逐件唯一异常边界，保留失败记录。
不自动覆盖、无限重试或随机挑种子。不将mask/深度的原始标签强称为整图生成GT。

## Validation / Sanity Checks
验证LUT插值通道/坐标/单位映射；验证官方Kontext调用没有误传strength/mask；
保存实际分辨率及全图原生成结果，复核所有结果数与输入摘要。只使用GPU7。

## Implementation Constraints
复用现有模型加载；提示词独立md，候选参数JSON；研究驱动文件放本目录。
小而清晰的函数，不引入新Agent/ComfyUI/服务/每图API调用，不修改训练环境。

## Deliverables
可复现修图入口、diffusion候选及运行记录、六件前后比较、综合结果笔记。
本轮同时推进两条路线；结论以实际图片而非实现完成为准。

## 后续机制比较：2026-10-27，前两组实际结果之后新增

LUT偏黄且没有解决CG感；Kontext整图在00489180新增黑孔，其他图摄影收益小。
Krea1024前3张重绘桌纹更明显，但没有足够证据支持摄影目标已达到。
下一项采用同一Krea与专用DepthControlNet，允许更强的整图材质重绘：原生512、40步、
strength0.65、guidance4.5；固定六件/种子/提示词，ControlNet scale=0.0与0.5分别运行。
两组均通过同一ControlNet管线编码相同深度，保证随机数消耗相同，比较控制残差的作用。
此对照采样mask全白，让目标CAD也能改变光色；保留整图raw，并另存原CAD回贴版。
背景mask方案无法研究目标材质改善，因此此项在实际运行前明确采用full_frame。
深度约束不是轮廓/孔槽保证，背景仍需审图。若图更像照片但产生
物件错误，不能默认为合格。此轮不更换样本、筛选seed，不扩大100件。

Depth权重来源Shakker-Labs/FLUX.1-dev-ControlNet-Depth，固定revision/摘要见准备记录。
输入使用渲染相机Z的逆深度，近白远黑，显式记录归一范围；官方训练来自
DepthAnythingV2，条件分布差异是实际限制。Krea+ControlNet组合需实测，不视为官方验证。

## 背景增强与目标空隙保护：Depth对照完成后新增

Depth-off/on均6/6完成，背景摄影纹理确有收益，但raw目标普遍被换成其他物体或消失。
深度仅保部分粗形，无法独立保证孔洞/轮廓。原像素回贴会留下外部残留。
据此新增depth_guard：512、strength0.65、guidance4.5、control0.5不变；提示词改为
不含手机/相机品牌的客观摄影描述；采样和合成保护原mask的凸包+6px，外侧8px羽化。
凸包包含孔洞/凹隙，这些背景像素也承载CAD结构证据。新增背景不能填原目标空隙。
代价是局部原背景保留，可能出现纹理/亮度边带，必须逐件检查。其他外围新形状仍需审图。
此项先固定六件，不挑seed；它同时改变prompt与mask，是明确记录的工程候选，不作单因子归因。

## 保护版分辨率候选（512前两件看图后追加，尚未执行时冻结）

512保护版避免了目标被替换，但背景键盘/玻璃样伪影与强烈反射仍需改善。
固定追加depth_guard_1024：同一prompt、control0.5、凸包保护，内部1024、strength0.5、
40时间表步，最终512。其初始sigma接近512/.65但并不相同，实际步数也不同，
这是工程候选而非纯分辨率因果实验。仍六件同seed，不挑图，不扩大100件。

## 明确表面材料：最后一组固定六件候选

1024保护版把原灰地面变成强镜面，虽然可作为材料变化，但与本办公室的低光泽地面
要求不符，且3张先看图仍有CG感。追加depth_guard_matte，仅把512保护版prompt改为
明确低光泽木桌、哑光灰vinyl地面、粉刷墙、纸张及黑塑料外设，其余参数/输入/seed不变。
不再泛泛要求“更多真实反射”。这是基于观察的材料语义指导，保留旧版本，不宣称
可单独证明某个词的因果。此轮之后汇总所有6件，不再自动扩大或无限扫参数。
