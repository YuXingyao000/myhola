状态：2026-10-26 已按本设计实现首版，代码位于 `packages/cad_scene_factory/step2/`。
工具及外围循环的验证状态见 [NOTE.md](NOTE.md)；尚未进行真实 LLM 的端到端位置搜索。

## 目标与边界

输入一个已验收场景，输出若干可复用的「支撑区域、落点、相机」组合，而非只返回一个 XYZ。
第一步由 Agent 选择候选区域；外围准备图片和对象索引是该步骤的输入准备。
一个场景允许找到多个位置，也允许没有合格位置，不能为了凑数降低条件。

本版用最长边上限 20 cm 的正方体代理，寻找已有空位或能够通过少量挪动获得的拍摄位置。
选区优先考虑支撑、尺度、背景和拍摄角度；当前被松散道具占用不构成自动淘汰理由。
真实 CAD 尚不装入。允许在场景副本中移动少量完整道具组，腾出局部空间，保留周围物件
及使用状态；建筑、家具、支撑面、固定设备、光照和材质保持原样。基础场景始终保持不变。

目标是像人在杂乱桌面上临时腾出地方拍照：零件处于画面重心，周围看得到被推开的物件。
拍摄区域的中心不要求等于桌面的几何中心，也不要求桌面整体变整齐。

正方体证明的是指定尺寸包络的支撑、空间与可见性条件，不证明具体 CAD 的稳定姿态、
孔槽可见性、金属材质或最终照片真实性。CAD 尺寸、姿态或镜头改变后必须重新检查。

## 三类职责

| 标记 | 执行者 | 能决定什么 | 不能代替什么 |
|---|---|---|---|
| F | 外围 Python workflow | 固定配置、调用顺序、逐候选状态、预算、记录、最终导出 | 不凭程序阈值宣布视觉真实性通过 |
| A | 同一个摆放 Agent，会话内按阶段续接 | 语义选区、完整物件分组、落点/机位/移动方案、前后图评价 | 不覆盖几何检查、不改阈值、不宣布人工已验收 |
| T | Blender / 几何工具 | 场景索引、表面测量、应用刚体变换、碰撞与投影计算、代理渲染 | 不靠对象名称或 AABB 顶面证明真实支撑 |

图中 A 是提示词驱动的结构化任务；F/T 必须有实际程序支持。提示词写「检查遮挡」不能
代替一次工具执行。Codex 自带的推理与可选工具循环位于 A 节点内部；外围控制节点之间
的顺序、重试和结束。当前聊天不参与运行时循环。

## 阶段与数据流

| 阶段 | Agent 的任务 | 外围与工具必须做的事 | 产物 |
|---|---|---|---|
| 0 准备证据 | 无 | 固定 scene.blend 版本、米制尺度、代理/相机参数；导出对象 ID、包围盒及带编号全景；必要时准备局部图 | scene_context |
| 1 提出区域 | 看场景，提出最多 K 个适合拍摄的区域，包括被小型道具占用的好位置；给出支撑对象 ID、粗略局部范围及理由 | 校验 ID、区域范围、去重和数量；同一桌面的远隔区域允许分别保留 | regions |
| 2 测量分类 | 无；不让 Agent 估算厘米数 | 测量真实表面、邻近可安置区域及占用；分别给出现有空位和扣除明确固定障碍后的潜在范围；分为直接可试、需挪物、不适用 | measurements、blocker_ids、active_regions |
| 3 联合提议 | 同时选择落点、机位、完整物件组及其移动终点；说明哪些周边物件应留在画面中；一次提出本轮活跃区域的方案 | 校验结构化返回及移动范围；只允许白名单道具组刚体平移/绕支撑法向旋转，家具、光照与材质不改 | setup_proposals |
| 4 检查并预览 | 无 | 每个方案从基础场景创建独立副本，应用本轮完整移动清单；检查移动物件与代理；通过后渲染同机位整理前/后图及可见性证据 | numeric_report、before/after_preview |
| 5 看图评议 | 对照前后图及报告，判断主体重心、周围杂乱保留、挪动自然程度、背景及光照；返回保留/调整/放弃及理由 | 数值失败不能被视觉意见覆盖；无图片的候选标为未看图；不能仅因物体还存在于场景就认定它仍在照片里 | visual_review |
| 6 状态更新 | 无 | 数值和视觉均通过则保留；可修正且预算剩余则进入下一轮；否则记录失败或未完成；已经通过的候选不重做 | active_regions、accepted、rejected |
| 7 导出 | 无 | 活跃集合为空后汇总全部候选、移动变换、全部尝试及失败项；准备人工审阅图集 | placements.json、前后预览、日志 |

输入的真实房间可以称 room.blend；表中 scene.blend 仅指固定的场景工程，并非要求改名。
汽车场景应使用 human_edit_01/build/room.blend，不能退回包含 PATCHES 盒子的旧工程。

## 三个提示词的输入与返回

所有返回均为带 region_id 的结构化数据，schema 由外围校验。示例字段是接口设计，
尚未生成实际候选。

| 请求 | 发送给 Agent | Agent 返回 |
|---|---|---|
| select_regions | 编号全景、对象索引、20 cm 需求、区域数量上限 | support_object_id、view_id、image_region_px、reason |
| propose_setup | 现有空位与潜在范围、占位物件及邻近空间、相机规格、最新失败原因/图片 | region_id、support_point_world、camera_position_world、look_at_world、move_groups、retain_in_frame |
| inspect_setup | 本轮同机位前后图与 numeric_report，按 region_id 明确配对 | region_id、keep/revise/drop、inspected_images、reason、suggested_change |

选区时允许 Agent 在编号图上画粗略像素区域，不要求它从照片猜测三维尺寸。测量工具使用
该视图的相机矩阵，将区域射线投向所选支撑对象的真实网格，获得世界坐标中的局部表面；
其他物件的占用仍然检查，不能因指定支撑 ID 而忽略遮挡。映射不明确或没有有效表面时
明确返回该候选未完成/不适用，不生成虚假的坐标。图像裁剪或缩放时保存像素坐标变换。

look_at_world 默认指向代理中心；support_point_world 则在底面。两者不能混用。
提议阶段不返回任意 Blender Python 程序，由外围把这些受限字段应用到场景副本。
move_groups 包含组 ID、成员对象 IDs、支撑物 ID、旋转中心和相对基础版本的平移/偏航角。
retain_in_frame 指出需要保留在照片周边的物件组；有移动时，必须包含被挪动且能解释腾位
动作的物件，不能全部搬到镜头外。没有必要挪动时允许 move_groups 为空。

## 第一版工具：四个入口就够

以下为工具职责；实际入口及文件分工见 `step2/README.md`。

1. `describe_scene(scene)`：返回稳定对象 ID、名称、类型、所属组、世界坐标包围盒、米制尺度、
   已有全景及对象编号图。ID 与场景版本绑定；名称辅助理解，不作为支撑证明。
2. `measure_region(scene, region, proxy_spec)`：在 Agent 选中的局部表面采样/求交，返回支撑
   高度、法向、有限边界、当前空位、潜在落点及邻近安置范围、占位物件和连接关系。
   潜在范围不等于已经可用，必须在执行移动后重新检查。只测候选局部，不先做全场景语义重建。
3. `preview_placement(scene, proposal, config)`：从只读基础场景创建临时实例，校验并应用
   道具组移动，加入代理与相机；统一检查并输出前后预览。返回数值报告、实际相机矩阵及
   指定周边组的可见性证据，不接受 Agent 自报数值。应用变换是该工具的一个内部步骤。
4. `export_placements(state)`：保存通过代理检查的位置、可用范围、相机、图片及全部失败。
   不需要为每个点复制完整素材包；记录基础场景摘要与变换即可。

2/3 是新工具能力。现有 room_tools.py 的 inventory/render 可复用；geometry.py 的
check_bbox_framing 与 visibility.py 的 find_blockers 可用于部分检查。现有
plan_support_placement 会平移整个环境，不适合本版「固定房间，放入物件」的逻辑。

## 空间与相机检查

- 支撑：落点属于真实有限表面；代理底面在允许高度误差内获得支撑，不能把物体 AABB 的
  顶面直接当作桌面。首版仅找近水平表面，暂不做重心或刚体稳定性模拟。
- 边界：20 cm 代理的占地范围与支撑面边缘之间保留指定余量；在桌面内部不等于在可用
  空间内部。潜在范围扣除固定占用；实际验收再扣除移动后的全部占用。台面污渍无需「清除」。
- 碰撞：使用渲染对象的 AABB 做保守检测，支撑接触允许，穿入不允许。按实际对象/几何片区
  建检测代理，不使用整个房间或 collection 的大包围盒。若建筑外壳合并为一整个网格，
  检测时按墙、地、顶的平面片区分别生成包围盒，不直接忽略外壳。
- 入镜：代理全部在近远裁剪及画面边界余量以内；计算投影框占比与中心偏差。
- 遮挡：检查相机到目标包围盒的有限保护体，不检查整个房间是否进入无限视锥。
  背景墙出现在画面里是正常的。用物体 AABB 可以保守误拒，报告返回阻挡物 ID；不能把
  AABB 相交直接宣称为实际像素必被遮挡，也不能只测试八条角点射线。
- 相机：不在实体内部或墙后；与代理之间有拍摄空间。首版不证明完整的摄影者行走路径。
- 数值通过与视觉通过分开。视觉关注代理大小是否协调、拍摄方向是否自然、背景是否
  有空间层次、主要光照是否读得清楚，以及是否像临时挪开物件拍照。正方体灰色表面的
  结果不作为金属反射验收。

当前可行落点集合可以理解为：支撑区域减去代理占地及边缘余量，再扣除所有障碍物扩张
后的范围；潜在集合仅扣除固定障碍。不明确能否移动的物件单独标记，不能把潜在集合当
作已经空出的空间。最终验收使用应用完整移动计划后的场景。
正式实现允许用局部采样网格近似；采样分辨率和容差需要记录，不能称为连续几何的严格证明。
位置提议每次仍要调用检查，不能仅凭采样范围粗图通过。

## 建议起步配置（待审阅，不是已验证的最优阈值）

| 配置 | 初始值 | 用途 |
|---|---|---|
| max_regions | 6 | 区域上限；不要求找到六个，多个相机不计为多个摆放位置 |
| max_revisions | 2 | 初稿之外最多两次整理/构图联合调整；失败终止，不无限「抽卡」 |
| max_moved_groups | 6 | 每个方案最多移动六个完整小道具组；这是上限，优先少动 |
| max_translation | 0.40 m | 同一支撑面上的局部移动初值；不允许搬走整套布景 |
| max_yaw_change | 45° | 初版只允许支撑面内偏航；不翻倒、不缩放、不变形 |
| proxy | 边长 0.20 m，世界轴对齐，哑光中灰 | 覆盖已约定 15–20 cm 尺寸上限；不用它评估目标金属材质 |
| support_margin | 0.02 m | 每侧支撑边缘余量；最小正方形连续区域约 24×24 cm |
| surface_slope / height_tolerance | 5° / 0.002 m | 近水平支撑的工程起点；测量时报告不平整和孔洞 |
| camera | 512×512，垂直 FOV 45°，roll 0 | 延续此前拍摄规格；位置、方位和俯仰可变 |
| clipping | near 0.01 m，far 100 m | 沿相机前向轴的裁剪深度；不代表固定拍摄距离 |
| surface_grid_step | 0.01 m | 候选局部支撑采样步长，边界附近另行检查 |
| collision_tolerance | 0.00001 m | 接触/穿入的数值容差初值，不代替表面高度容差 |
| preview | 64 samples，seed 8，固定场景原光照 | 看构图，不改变布景以迎合代理 |
| frame_margin | 16 px | 防止包围盒贴边、裁切 |
| projected_size | 投影框长边 / 512 在 0.35–0.65 | 初始构图区间，不代表图像面积比例 |
| center_offset | 投影框中心距画面中心 ≤ 短边的 0.15 | 给主要目标留近中心区域 |

上述数值统一放进配置并随结果保存；工具实现时用真实场景验证其行为，再固定首版协议。
20 cm 代理通过后，15 cm 的真实 CAD 投影会更小，实际导入阶段重新检查占比。
第一次实现继续使用 CPU、八线程、串行工具队列；不因为新增工作流就自动占用训练 GPU。

## 调用与循环：复用一个 Agent，按轮批量处理

为控制成本，不为每个位置创建一个 Agent，也不让每个区域各自独立开启完整会话。
每个场景新建一个摆放会话，只提供本场景证据、工作要求和工具契约，不带原制作长历史。

- 一次 `select_regions` 请求获得区域集合。
- 每轮一次 `propose_setup` 请求，批量提出当前活跃候选的落点/相机/移动清单。
- 外围逐候选从基础场景创建副本并运行工具；渲染按设备预算排队，各位置互不累积移动。
- 每轮一次 `inspect_setup` 请求，批量返回这些候选的前后图像意见。所有对象以 ID 对齐。
- 外围保留通过项，仅把需调整项及其失败原因、最新图片送入下一轮。最多两次调整。

因此默认上限是 1 + 2×3 = 7 个外围 Codex turn；这不是七次底层模型推理，也不是 token
上限，Codex 内部仍有自己的循环。真实事件、token 和耗时分别记录；输出格式/调用故障
单独记录，不能悄悄多开无限纠错回合。若平台调用或工具执行失败，保存 incomplete 和
已有结果；基础设施失败不伪装成某个位置几何不合格。

提示词只能表达职责，不能形成权限隔离。外围每次从固定场景版本读取，并核对摘要；只
把白名单字段中的代理/相机变换、有限道具组变换用于生成副本预览。基础场景若被改动则
本轮无效并停止；如要
严格阻止写入，还需实际只读挂载/权限，不能只在 prompt 中写「禁止修改」。

## 最小产物与验收语义

每个候选至少记录：

- `scene_id / scene_hash / region_id / support_object_id`；
- 世界坐标支撑点、法向、可用区域；世界轴向和米制约定；
- 代理尺寸、代理变换、相机变换、FOV、分辨率、近远裁剪；
- 完整道具组定义、相对基础场景的移动清单、原/新变换和支撑、保留入镜组；
- `status`、数值检查值与阈值、阻挡物 IDs、视觉意见、预览路径；
- 每次提议/调整、会话及用量，基础场景与工具版本。

终态固定为 `proxy_ready`、`rejected`、`incomplete`；人工意见另存
`human_review`。其中 proxy_ready 只表示当前代理与相机通过本版数值/视觉检查。
`requires_rearrangement` 是选区后的属性，不是把好位置搁置不处理的终态。
清理预算内无法完成的候选记录 rejected 及实际原因，不回写成已经可用。
零个 proxy_ready 也应正常导出全部证据，不能默默更换输入或删除失败候选。

首轮交付给用户：区域编号总览、各位置的原始/整理后正方体照片、移动清单、尺寸与机位，
以及未通过项及理由。原始对照图不放代理，防止在尚未腾位时把正方体插进其他物件。
两图采用同一机位、灯光和成像参数；机位变更时重拍对应原始对照图。
人工审阅是结果交付后的环节，不在每次 Agent tool call 中弹窗。

## 局部整理的具体约束

1. **保持物件完整。** 托盘及其内工具、盒子与关联盖子按完整组移动；Agent 提议组成员，
   程序核对父子关系、实例及成员重叠，避免漏掉零件或父子重复变换。固定台钳、设备线缆、
   管线及连接不明确的物件不在首版移动范围。可动性中的语义判断作为假设记录。
2. **少动、近移。** 优先处理侵入目标占地/余量或挡镜头的物件，将它们平移到同一支撑面
   的邻近区域，允许少量旋转。清理面积由目标包络及拍摄需要确定，不要求整桌清空。
   比较方案时优先少动几个组、较小总位移；不凭空构造一个「自然程度」数值评分。
3. **外围验证终态。** 道具组不丢失、不隐藏、不缩放、不改材质；移动后仍有支撑、不越界、
   不新生穿插，目标和相机满足原有检查。检查包括与未移动道具的冲突，以及组间冲突。
4. **画面里保留痕迹。** Agent 指定 retain_in_frame；工具输出其实际可见像素/掩码，
   不以包围盒投影入镜代替实际可见。初版非零可见仅作必要条件，Agent 看前后图确认物件
   可辨认、分布自然，不能只剩边缘几像素，也不能整齐排列成展示边框。局部遮挡允许。
5. **主体仍是视觉重心。** 原目标入镜、中心偏差与占比检查继续保留；Agent 看图检查周边
   是否抢主体、背景是否被清得过空。无需把主体放在整张桌子的几何中心。
6. **每次重建副本。** 本轮 moves 是相对于基础场景的完整替换方案，不叠加上轮位移。
   不同拍摄位置对应不同变体；导出基础场景摘要及变换，不把所有位置的清理累加到一个房间。

初版制作「像人为推开后的状态」，不模拟手、连续推动轨迹、摩擦或刚体动力学。
数值检查针对移动终点，不能宣称已经验证从原位置推到终点的全过程可行。
随机变化可在之后用于小幅位置/朝向扰动，并固定 seed、重新检查；第一版先用明确方案，
不要靠独立随机打乱 Blender 子对象制造杂乱。

## 代码边界与首版取舍

- `step2/workflow.py`：普通 Python；候选集合、有限循环、调用与记录。
- `step2/tools.py`：Blender JSON 入口；操作分为 `scene.py`、`spatial.py`、`preview.py`。
- `step2/prompts/CONTRACT.md` 与三个阶段 `.md`：中文先审阅，确认后转英文。
- 结构化返回 schema、固定配置分别存 JSON。Python 仅组合运行数据，不承载长提示词。

按实现前用户要求，采用耦合的实验输入/输出，不建设通用恢复、锁或防御性校验体系。
工具/调用故障直接抛出，已经落盘的结果保持 incomplete。选区阶段同时定义可移动组；
首版所有被移动的组均要求保留入镜。局部测量报告 free / movable / fixed_or_unknown，
固定性是 Agent 的语义假设；终态必须重新数值检查。已有全景图作为输入，不重复渲染六图。

复用现有 `call_llm.run_codex_turn` 的调用和事件记录；不改动 scene generator 的制作流程。
最小实现顺序为：先工具能够测量一个真实局部并生成代理预览，再接区域提议和有限循环。
到真实 CAD 阶段仍须补充真实几何接触、姿态、孔槽可见性与材质检查。
