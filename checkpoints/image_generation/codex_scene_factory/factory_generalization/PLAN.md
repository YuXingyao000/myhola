# 小型机加工车间：独立生成测试

## 目标与输入

按用户确认的计划，只给场景需求、素材工具和 Shed 质量示例，由 Agent 选择单体素材并搭建完整工厂空间。不给现成工厂工程，不由主控手工修改生成的布景。首先解除历史 Shed 专用限制，再冻结本次工具与提示词；这项接口解耦与生成质量分开记录。

输入为 `PROMPT.FACTORY.EXAMPLE.md`、只含图片／说明的参考包、共享素材缓存及明确 GPU。参考模式为 `quality_only`，原 `adapt` 默认行为保留。素材获取复用现有工具，兼容旧平铺清单和房间对象清单；实际文件及来源保存在模板内。关键资产不可用时如实保留缺口。

## 固定协议

- Codex：ChatGPT 账号，gpt-6-astra，ultra；新建工厂会话，不复用 Shed 制作会话。
- Blender：5.2.2 LTS、Cycles／OPTIX；执行前确认选定 GPU 无其他计算作业。
- 快速预览 64 samples；外围六视角 128 samples、seed 8；最多三次外围返修。
- 六个视角角色保持；`workbench_*` 在此表示核心机加工作业区及设备细节。
- 维持制作 → 独立重建／渲染 → 只读审阅 → 有限返修状态机。全部失败与版本保留。

## 输出与判定

模板脚本、机位、素材清单、可重建场景、六图与报告，以及调用、用量和返修记录。技术检查覆盖文件、资源摘要、依赖和六图完整性；视觉判断依据场景用途与尺度、主要表面／设备、光照／反射及多视角一致性，不捏造总分。

Agent 的 ready 只表示提交人工审阅。用户批准继续为 pending；首轮人工意见与后续修订分别保留。本轮结果可为完成候选或有具体原因的 incomplete，不以降低为维修桌场景来替代工厂要求。

## 实现验证

验证仅图片参考无需基础工程、默认 adapt 保留、素材工具与缓存注入、两种清单合并、真实文件复制／摘要及坏摘要在 Blender 之前被拒绝。原工作流状态机回归保留。轻量联网素材下载单独测试，不把接口通过当成生成质量结论。

代码位于 `/mnt/d/python_room_generation` 的 `codex/room-generation` 分支；原 Shed 模板及历史快照保留，不自动迁移到新工具版本。新的调用与成果独立存储，不写入训练工作区。
