# 支撑面修复执行约定

## Task

修复 Step 2 测量网格与 Cycles 位移后表面不一致的问题；复验原五个位置及原五件 STL。
旧 100 件任务继续暂停，不调用 Agent，不覆盖旧场景和产物。

## Assumptions

当前支撑是近水平网格面；微纹理通过 Bump/Normal 表达，不依靠渲染期几何位移。
宏观起伏应存在于可测量网格。本次不实现位移烘焙或物理模拟。

## Inputs

已有 Step 2 场景、候选区域/方案、配置及 ready；原五件测试的模型/尺度/seed/材质。

## Outputs

独立 prepared_scene.blend、材质处理记录、原五位置的新测量/试拍/深度验收、新 ready，
以及固定五件重拍与前后对照。所有路径/摘要指向修复副本。

## Processing Protocol

选区后复制被选支撑对象的位移材质，设为 BUMP；使用对象级材质槽避免污染共用材质
或网格的其他对象。保存新场景后更新主流程的 base_scene/hash，再测量和试拍。
每个方体试拍同时输出支撑面 ID mask 与 Z EXR，反投影可见的局部支撑面，核对其高度。
ready 导出该验收结果。Step 3 只消费通过的新 ready，在同一场景中逐件核对最低点。

## Metrics

局部可见支撑面的像素数、渲染高度 min/median/max、相对保存高度的最大绝对误差；
模型底端相对渲染高度中位数的距离。继续使用现有 2 mm 容差，不扩大容差。

## Decision Rule

无可用支撑像素或任一被测表面高度超出容差时不通过；方体其他检查也必须通过。
Step 3 要求 ready 中存在通过的渲染验收，再核对实际模型底端。
数值通过与人工视觉审阅分开；这不证明整个被遮挡表面的连续几何或物理稳定。

## Edge Cases

共用材质只改变支撑对象的槽；已是 BUMP 的表面保持原设置。没有材质则不修改。
旧 ready 缺失渲染验收字段必须重新验收，不自动视为通过。
图片/深度缺失直接报错；空/非有限深度不产生有效验收。保留全部失败产物。

## Validation / Sanity Checks

用原场景验证新增检查能拒绝约 4.85 mm 的位移差，再验证修复场景通过。
核对原 blend 摘要不变、非支撑共用材质不变、选中网格坐标不变；验证当前主循环
写出的 request/state/ready 使用同一副本与摘要。复拍原五个位置/模型并核对深度与接触。

## Implementation Constraints

保持现有组织；scene.py 负责场景副本，单独 support.py 负责渲染高度检查，
workflow 中只加入一个显式准备步骤。无新 Agent、恢复框架或批量重试。

## Deliverables

代码、验证数值、五件前后对照和更新的说明。旧任务保持暂停，新批量运行另行决定。
