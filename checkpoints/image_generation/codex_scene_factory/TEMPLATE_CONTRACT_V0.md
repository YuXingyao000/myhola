# 布景模板生成协议 v0

## Task

生成可复用的布景模板及程序化零件材质配方，供固定渲染器装入不同 CAD 批量拍摄。**模板制作输入是零件集合的占用包络 BoundingBox、固定拍摄预设及分项自然语言需求；具体 STEP 属于后续批量渲染输入。**

状态：2026-10-12 需求草案，未实现或渲染。用户明确产物为“布景模板生成”；此版本取代 [上一轮单件输入讨论](SCENE_CONTRACT_V0.md) 作为当前最小制作协议。整体预算、复现与验收原则沿用 [工程方案](PLAN.md)，代码边界见 [代码组织方案](CODE_LAYOUT.md)。

## Assumptions

- 用户已确定：归一化零件位于原点、保持给定姿态；相机位置 `(2,2,2)`、看向原点，输出 `512×512`，FOV **`45°`**。用户已纠正此前记忆中的 `90°`；当前协议不再使用它。
- 实现默认建议：数学右手系、Z 向上；透视、方形像素、零镜头偏移，look-at 原点，以世界 Z 为向上参考且无额外 roll。无需用户重复填写欧拉角，也不由 GPT 猜测。
- 源码事实：旧 `render_single_view.py`／`render_cube24.py` 相机是 `(2,2,2)→原点`、FOV `45°`。旧 single-view 归一化把包围盒中心移至原点，最长边缩放为 `1.8`。这不等于新输入已经核验或必须继承旧配置；本轮未改旧脚本。
- 归一化坐标不自动代表米。模板与目标共享明确的归一化单位；采用物理尺寸资产时显式配置单位映射，不能让模型猜真实零件尺寸。统一换算需一致作用于 CAD、相机、环境和材质长度参数。
- 目标为刚制作完成的零件，材质仅用常量／程序函数，不用图片贴图。背景可使用允许资产。源几何、姿态和相机受保护。
- 平坦支撑区可以属于桌面或地面，不要求对象类型为 Plane。允许尖点接触，不做重心／刚体模拟。
- 用户确认的职责：GPT 制作布景及程序材质，外围固定程序负责摆放关系、相机、检查和拍摄。当前保持 CAD／相机不动而调整模板实例是实现此职责的具体策略；模型无权自行更改摆放协议。
- `Needs confirmation`：正式归一化范围与姿态集合、首次占用包络、物理单位映射和制作预算。此阶段不启动批量生成。

## Inputs

### 模板制作输入

| 输入 | 含义 |
|---|---|
| `template_id`, `seed`, `protocol_version` | 制作身份与版本 |
| `target_envelope` | **预期零件集合**在支撑局部坐标下允许占用的 BoundingBox；明确坐标、单位、最小／最大角和余量 |
| `placement_range` | 原点固定的零件可能具有的最低点高度范围，由归一化合同／预处理生成 |
| `camera_profile` | 固定位置、look-at、向上参考、FOV、分辨率及来源 |
| `creative_brief` | 支撑物、周围环境／布置、照明三项简短自然语言 |
| `material_policy` | 新零件的程序化材质族及允许变化范围；不按 CAD identity 固定绑定 |
| `asset_allowlist`, `budgets` | 场景允许资产和作者／预览／修复预算 |

包络是可用空间，不是要被渲染的实体，也不代表每个 CAD 的接触形状。模板支撑局部顶面为 `z=0`。若零件世界点为 `p`、最低点为 `h`，支撑局部点为 `q=p-(0,0,h)`；输入包络需覆盖允许零件的这些 `q`，不能直接拿居中包围盒作为底面对齐后的包络。

框架可从归一化／姿态合同推导保守包络，或从预定集合得到紧凑包络。不能从一件样例外推所有 CAD。相机在支撑局部坐标下为 `(2,2,2-h)`；因此模板必须覆盖相应高度范围，而不是仅验证一个拍摄位置。

### 分项自然语言

```yaml
support: 干净的工作台，表面稍微粗糙
surroundings: 普通维修间，背景有少量工具，布置疏朗
lighting: 左侧柔和窗光，整体明亮，零件细节清楚
```

这是三个分别回答的问题，不是固定枚举或数值表格。每项提供最低程度意图即可，也可显式写“由模型设计”。不要求用户提供灯具瓦数或坐标。模型完成具体设计后保存程序、实际参数与允许变化范围，以及 `user`／`default`／`model`／`geometry_derived` 来源。

需求正交化指分别表达、替换和比较，**不等于物理独立或独立随机抽取全部组合**。窗口、光源、墙面反射与金属倒影需要统一协调。三项联合为空或与硬条件冲突时报告缺失／冲突；语法完整不等于真实感或语义已经被证明满足。

### 批量拍摄输入

具体 STEP／实体／姿态、冻结模板版本、材质配方、实际外观参数与 seed。由固定程序预处理和渲染，不作为逐图 GPT 输入。

## Outputs

- `build_scene.py`：参数化环境程序，构造背景几何／材质、场景灯光及 World；环境根节点可整体平移，不导入目标或修改相机。
- `template.json`：适用包络、真实支撑对象／表面区域、局部支撑平面、清空区、参数范围、允许组合及资产摘要。
- `material_recipes.json`：可复用的程序化零件材质配方与参数范围；由固定装配器检查并应用，不允许位移变形、透明挖孔或改变目标。
- 资产依赖、制作轨迹、开发预览与独立验收报告；单件通过不得写成支持所有 CAD。

批处理输出 RGB、目标 mask 和完整记录：CAD／模板／材质版本、相机、实例化变换、实际参数、seed、状态与耗时。审计 passes 沿用 [PBR 方案](../PLAN.md)。

## Processing Protocol

1. **准备制作请求**：框架解析包络、最低点高度范围、固定拍摄预设和三项创作意图；具体 STEP 不是模板作者的必需输入。
2. **制作模板与材质**：Codex 使用空间包络／代理形状布景并编写材质配方，补全具体参数。代理物体不进入最终照片。
3. **开发预览与有限修复**：固定工具在既定形状／CAD 面板上实例化，返回图片和接触、碰撞、遮挡等报告。修复对象为模板，不能改目标／相机或检查面板。
4. **独立验收与冻结**：在作者未见的 CAD／参数面板验证适用范围；技术状态和视觉审阅分别记录，保存程序、资产和参数分布。
5. **批量准备 CAD**：固定程序读取 STEP，核对单位与实体，受控三角化，保留法线、硬边、面对应和变换；导入后核对坐标和重排。正确归一化的输入不盲目再次归一化。
6. **实例化**：保持 CAD 与世界相机不动，求当前 CAD 的 `h=min(z)`，将模板环境根节点沿 Z 平移 `h`。桌面、背景与场景灯光共同移动；World 的方向与强度单独记录，不虚构其平移。固定程序赋予零件材质。
7. **检查并拍摄**：检查支撑局部目标位于包络内、真实接触、无穿插、相机有效且无额外遮挡；渲染、保存配置及失败，逐图不调用 GPT。

第 6 步是模板实例化，不是重新生成模板。同一个居中包络中的零件最低点不同，不能用代理盒底部代替真实 CAD 底部。环境平移会改变背景构图和相对相机的照明，所以每个实例仍检查和留档。

当前固定预设下，世界支撑高度为 `h`；零高度只属于模板局部坐标。此前共同平移 CAD／相机到 `z=0` 的方式不再作为当前默认。

| 拟议工具 | 职责 |
|---|---|
| `inspect_request` | 读取包络、固定相机、创作意图、允许资产及预算 |
| `check_template` | 检查真实支撑、几何／材质接口、根变换、资产和受保护字段 |
| `render_preview` | 固定程序在开发面板装入不同零件、赋材质并渲染，返回拼图和诊断，计入预算 |
| `submit_template` | 提交不可变版本；控制器强制验收，不由模型自报成功 |

模板版本绑定程序、参数和依赖摘要；修改后旧报告不可复用。先用顺序脚本完成单次模板制作循环，不以数据库或八卡调度为启动前提。

## Metrics

- 适配：预定 CAD／尺寸／长宽高比例／最低点高度范围内的实例化成功率，越界与技术错误分开。
- 几何可见性：入画、裁切、接触、穿透、外物遮挡及目标／相机合同一致性。
- 外观：材质、环境、照明与结构可辨性分别审阅；技术通过不等于真实感合格。
- 复用与成本：每模板使用量、参数覆盖、跨模板背景近重复、模板制作成本和每图渲染成本；重复模板大量出图不等于场景多样性。

## Decision Rule

源几何、固定视角、平面接触、无穿插和规定可见性属于硬条件。三项创作需求保留实现自由，视觉审查检查其效果。稳定性不作为当前条件。预算耗尽保留失败；未经视觉审阅为 `unreviewed`。

## Edge Cases

- 归一化范围不明、单位／实体错误、非法网格或非有限坐标：准备阶段报错，不由模型猜测。
- 当前零件越界：`outside_template_domain`，不擅自缩放目标或改变相机。
- 包络底部不等于真实底部：按当前 CAD 的 `h` 实例化环境，不以代理盒接触自证。
- 支撑有孔、起伏或错误高度：`support_geometry_mismatch`；支撑区域禁用真实 displacement。
- 道具没有碰到 CAD 但挡住相机：新增遮挡检查失败。
- 尖点支撑／重心偏移：允许，`stability_status=not_evaluated`。
- 缺资产、构建错误、超时、预算耗尽：记录状态与成本，不无限重试。
- 有预定请求但全部失败时成功率为 0；分母为零时为 null。

## Validation / Sanity Checks

实施时先核对坐标转换与归一化。开发／验收覆盖高瘦、扁平、细长、带孔、凹形及尖点接触，检查不同 `h` 下 CAD／相机不变、环境根正确平移、真实接触与遮挡。验收面板独立，不以单件或单个最佳 seed 代表复用性。

本轮仅验证文档结构、链接与示例语法，未进行几何、渲染或真实感验证。

## Implementation Constraints

模板与 CAD 分别版本化。作者制作环境和材质；固定渲染器掌握目标、相机、实例化、检查和输出。模型调用发生在模板制作与修复阶段，批量拍摄复用冻结产物。
