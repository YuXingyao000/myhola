# Claude Code Guidelines — Data Preparation and Generation

The canonical instructions for this directory are `AGENTS.md`; read it before changing data tooling. This file is a summary only. The repo-wide entry point is the root `CLAUDE.md`.

## Scope

The core work is paired image data generation and data quality evaluation for single-photo B-Rep reconstruction. Images generated by FLUX editing are **synthetic realistic images**, not real photographs; `real_photo.npz` is a historical interface name and does not prove real capture. Validate quantity, photo style, and downstream usefulness separately; image count or visual appeal is not evidence of correct labels.

Work method: review inputs/contracts/artifacts first, define evaluation dimensions and failure handling, freeze the protocol and comparison data, establish a baseline, then propose falsifiable changes. Do not immediately retune prompts, guidance, materials, or generators when a problem appears.

## Runtime Contract

Use `dataset.py` and the actual Hydra config, not historical READMEs or filenames.

| Asset | Contract |
|---|---|
| Raw geometry | `raw_data_root/{model_id}/data.npz` |
| Grayscale/sketch | `condition_data_root/{model_id}/imgs.npz`, keys `svr_imgs`, `sketch_imgs` |
| Photo-style condition | `condition_data_root/{model_id}/real_photo.npz`, training reads `flux` |
| Rotated latent | `cached_latent_root/{model_id}_{rotation_id}/features.npy`, usually `[num_faces, 64]` latent stats |
| Optional visibility | `visibility_root/{model_id}/view_{rotation_id:03d}/visibility.npz` |

- `rotation_id=0` is identity. Latent, condition image, face adjacency, and visibility must use the same object, rotation, and face indices.
- A single `flux` image `[H,W,3]` supports identity only; rotation augmentation needs `[24,H,W,3]`.
- `real_photo_ratio>0` does not support `cached_condition=True`; check validation/test photo ratios in the actual loader config.
- The loader explicitly rejects legacy `natural_img`/`natural.npz`. Do not rename old formats or add silent format guessing.
- The real-photo preparation script copies an arbitrary valid `data.npz` as loader placeholder geometry; it is not photo GT, so never compute reconstruction accuracy from it.

## Records and Validation

- New image-generation plans, protocols, audits, and results go under `checkpoints/image_generation/<topic>/` with why, implementation, status/results, and links. Do not append to `experiments/`.
- Filter dry-run: `python tools/filter_deepcad_v7_lists.py --dry-run`. Audit tooling defaults report to a historical `experiments/2026-06-07/` path — pass explicit report/output paths.
- Report existence checks separately from array-read checks; neither certifies that pairing, views, or geometry are correct.
- SAM2 silhouette IoU, DINO similarity, and CLIP scores are auxiliary screening signals, not certification of geometric correspondence or realism.
- Split by source CAD/geometry family before deriving views, materials, and generation variants; same-source variants must not cross splits.
