## Overview

HoLa-BRep generates CAD models in **Boundary Representation (B-Rep)** format from multi-modal conditions (images, point clouds, text) via a two-stage pipeline:

1. **Stage 1 — VAE**: Encodes B-Rep geometry (faces + edges) into a compact holistic latent space that simultaneously captures topology and geometry.
2. **Stage 2 — Conditional Diffusion**: Generates face latent tokens from conditions, then decodes them into full B-Rep models with surface/curve geometry and topological connectivity.

## Installation

### Prerequisites

- Linux (tested on Ubuntu 22.04) or Windows (WSL2)
- NVIDIA GPU with CUDA 12.4+
- Conda

### Setup

```bash
# 1. Clone
git clone https://github.com/your-repo/HoLa-BRep.git
cd HoLa-BRep

# 2. Create conda environment
conda env create -f environment.yml
conda activate hola-brep

# 3. Install project
pip install -e .

# 4. Build PointNet++ CUDA ops (required for point cloud condition)
cd thirdparty/Pointnet2_PyTorch/pointnet2_ops_lib
pip install -e .
cd ../../..
```

## Data Format

### B-Rep Geometry Data (`data.npz`)

Each CAD model is stored as a NumPy compressed archive with the following arrays:

| Key | Shape | Description |
|-----|-------|-------------|
| `sample_points_faces` | `[num_faces, 16, 16, 6]` | Face surface points (xyz + normals) on a 16x16 UV grid |
| `sample_points_lines` | `[num_edges, 16, 6]` | Edge curve points (xyz + normals) with 16 samples |
| `face_adj` | `[num_faces, num_faces]` | Face adjacency matrix |
| `edge_face_connectivity` | `[num_edges, 3]` | Per-edge: (edge_id, face_id_1, face_id_2) |
| `zero_positions` | `[num_neg_pairs, 2]` | Negative face pairs (no shared edge) |

### Condition Data (per model directory)

| File | Content |
|------|---------|
| `imgs.npz` | Multi-view renders: `svr_imgs[24, H, W, 3]`, `mvr_imgs[...]`, `sketch_imgs[...]` |
| `single_view.npz` | Real-photo style image: `flux[H, W, 3]` (generated by FLUX.1-Kontext) |
| `pc.ply` | Point cloud: 10,000 points with normals |
| `text.txt` | Text descriptions (3 difficulty levels) |
| `img_feature_dinov2.npy` | Pre-cached DINOv2 features (optional, for faster training) |

### Cached Latent Features (for Stage 2)

Pre-computed VAE latent features stored as:
```
<cache_root>/<model_name>_<rotation_id>/features.npy  # shape: [num_faces, 64]
```
The 64 dimensions are `[mean(32), std(32)]` from the VAE's Gaussian bottleneck.

### Dataset Preparation

> Dataset download links will be available upon publication.

To prepare your own data, see scripts in `src/brepnet/data/`:
- `extract_brep_from_step_half_structure.py` — Extract B-Rep geometry from STEP files
- `extract_imgs.py` — Render condition images

## Training

All training is managed through a single entry point with Hydra config composition:

```bash
python -m src.brepnet.train --config-name <train_config> [overrides...]
```

### Stage 1: VAE Training

```bash
python -m src.brepnet.train \
    --config-name train_vae \
    model=vae_light \
    dataset.data_root=/path/to/brep_data \
    dataset.train_dataset=/path/to/train.txt \
    dataset.val_dataset=/path/to/val.txt \
    dataset.test_dataset=/path/to/test.txt \
    trainer.devices=1 \
    trainer.batch_size=4
```

### Stage 2: Diffusion Training

```bash
python -m src.brepnet.train \
    --config-name train_diffusion_white \
    dataset.latent_root=/path/to/cached_latents \
    dataset.condition_root=/path/to/condition_data \
    model.autoencoder.checkpoint=/path/to/vae.ckpt \
    trainer.devices=8 \
    trainer.batch_size=64
```

### Available Configurations

| Config Group | Options |
|---|---|
| `model` | `vae`, `vae_light`, `vae_light_exp`, `diffusion` |
| `condition` | `none`, `single_img`, `multi_img`, `sketch`, `point_cloud`, `text` |
| top-level config | `train`, `train_vae`, `train_diffusion_white`, `train_diffusion_real`, `train_diffusion_topo_bias` |

### Quick Start Scripts

```bash
# Edit paths in scripts/train.sh, then:
bash scripts/train.sh vae
bash scripts/train.sh diffusion_white
```

## Inference

```bash
python -m src.brepnet.inference \
    --diffusion-weights /path/to/diffusion.ckpt \
    --autoencoder-weights /path/to/vae.ckpt \
    --condition single_img \
    --input /path/to/images/ \
    --output-dir /path/to/output/
```

The inference pipeline:
1. Extract condition features (DINOv2 / PointNet++ / Text encoder)
2. Run DDPM sampling (1000 steps) to generate face latent tokens
3. Decode latents via frozen VAE → face/edge geometry + topology
4. Post-process with PythonOCC → output STEP files

## Evaluation

```bash
# Run evaluation metrics
python -m src.brepnet.eval.run \
    --pred-root /path/to/predictions \
    --gt-root /path/to/ground_truth \
```

## Experiment Workflow & Agent Skills

Day-to-day research is driven by two agent skills plus two living docs:

| Path | Role |
|------|------|
| `skills/brepnet-experiment-planning/SKILL.md` | Plan & set up one experiment day (confirm goal → reflect against the long-term target → check literature → design experiment → write scripts/commands → smoke test only). |
| `skills/brepnet-experiment-notes/SKILL.md` | Write the day's report under `experiments/YYYY-MM-DD/NOTE.md` (note-first: why / implementation / result, with clickable links). |
| `experiments/ROADMAP.md` | Single source of truth for the long-term goal, current phase, recent progress, open questions, anti-goals. Read first, update after conclusions. |
| `experiments/REFERENCES.md` | Curated reading list (foundational + last-3-years papers). |

`skills/` is the **canonical source**. Each tool discovers skills from its own directory, so the two `SKILL.md` files must be copied into each tool's skills folder:

| Tool | Skills directory | Scope |
|------|------------------|-------|
| Cursor | `.cursor/skills/<name>/SKILL.md` | project (committed) |
| Claude Code | `.claude/skills/<name>/SKILL.md` | project (committed) |
| Codex | `~/.codex/skills/<name>/SKILL.md` | home (per-user; **no repo `.codex/` folder**) |

> Codex only reads skills from the home directory (`~/.codex/skills`), which is why there is no `.codex/` folder in the repo, unlike `.cursor/` and `.claude/`.

After editing a skill under `skills/`, re-sync the copies:

```bash
for name in brepnet-experiment-notes brepnet-experiment-planning; do
  for tool in .cursor .claude; do
    mkdir -p "$tool/skills/$name"
    cp "skills/$name/SKILL.md" "$tool/skills/$name/SKILL.md"
  done
  mkdir -p "$HOME/.codex/skills/$name"
  cp "skills/$name/SKILL.md" "$HOME/.codex/skills/$name/SKILL.md"
done
```
