  诊断分析：为什么你的实验效果不好

  读完你的代码和论文后，我认为核心瓶颈不在VAE，而在条件注入机制和训练策略。让我
  逐层分析：

  1. 架构层面的关键问题

  看你的 Diffusion_condition 类（diffusion_model.py:109），你的 conditioning
  pipeline 是：

  DINOv2 (frozen) → img_fc (2层MLP) → cross_attn_add_cond (4层
  TransformerDecoder)
      → cross_attn_post_proj → 加上 time_embed → 24层 TransformerEncoder
  backbone

  问题1：条件注入太浅。 你的图像信息只在 denoising backbone
  的入口处注入了一次。之后的 24 层 TransformerEncoder
  里再也看不到图像了。对于白模图片，这够了（因为白模和CAD之间的mapping很直接）；
  但对于真实照片，模型需要在每一层都能反复参考图像信息来消歧义。

  问题2：对齐loss太粗糙。 你的 clip_style_symmetric_infonce 是对整个 30-token
  序列做 mean pooling →
  单个256维向量的对齐。这只对齐了全局语义，完全丢失了局部几何对应关系。

  问题3：你的 layerwise_img_adapter 是关闭的。 代码里默认
  layerwise_img_adapter=False（line 119）。这个组件（ZeroInitImageAdapter）正是
  你需要的——它在每N层注入图像信息——但你可能没用它。

  2. K16/32 实验告诉我们什么

  ▎ valid rate 上去了，但 Chamfer/F1 没变

  这非常关键——它告诉你：你的 diffusion model 已经学到了大致正确的 latent
  分布（所以能生成 valid 的形状），但condition 提供的几何约束太弱，无法引导
  latent 到正确的位置。换句话说：

  - 不是 "模型不能生成好形状" 的问题
  - 而是 "模型不知道给定这张图片应该生成哪个具体形状" 的问题

  这进一步证实瓶颈在 conditioning mechanism，不在 VAE。

  3. 为什么改 VAE（3DShape2VecSet 风格）没用

  你把 encoder 末端加了 learnable query + cross attention 来生成固定 30×32 的
  token set。问题是：

  - HoLa-BRep 的 VAE 已经通过 GATv2Conv + Transformer 做了很好的 face-level
  信息聚合
  - 你的改动改变了 latent space 的结构，但 diffusion model 的条件注入仍然太弱
  - 相当于换了个瓶子，但水龙头（condition）还是一样小

  我的建议方向（按优先级排序）

  方向1（最推荐，成本最低）：强化条件注入 —— 参考 IP-Adapter 做逐层注入

  核心思路：你已经有 ZeroInitImageAdapter 和 layerwise_img_adapter
  的代码了！先把这个打开并优化。

  具体建议：
  - 打开 layerwise_img_adapter=True，设置 
  layerwise_img_adapter_every=1（每层都注入）
  - 冻结你已训练好的 denoising backbone 的权重
  - 只训练 img_adapters + img_fc + cross_attn_* 部分
  - 这类似于 IP-Adapter (https://arxiv.org/pdf/2308.06721)
  的思路：在每层加轻量级 cross-attention，zero-init 保证训练稳定

  为什么这可能有效：原论文白模版本之所以work，是因为 DINOv2 从白模提取的特征和
  CAD 几何高度相关。对于真实照片，需要更强的、持续的条件注入来让模型学会从复杂视
  觉信号中"反复提取"几何信息。

  方向2（推荐，有理论依据）：加入 Classifier-Free Guidance

  我看到你的代码仓库里已经有 CFG 的推理代码（sample_condition_cfg.py），但你的
  Diffusion_condition 训练代码里没有 condition 
  dropout。原论文的多条件版本（Diffusion_condition_multimodal，约1120行）有
  learned_uncond_emb，但你的单图版本没有。

  具体做法：
  1. 训练时以10-20%概率把 condition 替换为全零（或 learnable uncond embedding）
  2. 推理时用 CFG：pred = pred_uncond + s * (pred_cond - pred_uncond)，s=1.5~3.0
  3. 对你的问题，可以尝试 time-dependent CFG：高噪声时 s 大（约2.5），低噪声时 s
   小（约1.0）

  为什么关键：CFG 本质上是放大条件信号的影响力。你的 K16/32
  实验证明条件太弱，CFG 是直接增强条件影响力最简单的方式。

  方向3（推荐，中等成本）：多粒度对齐替代全局 InfoNCE

  你当前的对齐 loss 是：30个face token mean → 1个向量 vs 257个image token mean →
   1个向量。

  改进方案（参考 LTM3D (https://arxiv.org/abs/2505.24245) 的 prefix learning）：

  # 替换全局 InfoNCE 为 token-level 对齐
  # 1. 用 cross-attention 从 image tokens 里 "读取" face-level 的对应关系
  face_queries = self.face_align_query(cad_align_src)  # [B, 30, 256]
  img_kv = self.img_align_kv(img_memory)               # [B, 257, 256]
  # cross attention: face queries attend to image tokens
  aligned_face = cross_attn(face_queries, img_kv, img_kv)  # [B, 30, 256]
  # token-level L2 regression (not contrastive!)
  align_loss = F.mse_loss(aligned_face, face_queries.detach())

  或者更好的：直接预测 latent token 作为 reconstruction prior（LTM3D 风格）：
  - 从 image feature 直接 regress 一个粗糙的 face latent 作为 diffusion
  的初始化/额外condition

  方向4（中等成本，应对domain gap）：两阶段 pipeline —— 图像 → 中间3D表示 → 
  B-Rep

  这是 Img2CADSeq (https://arxiv.org/abs/2605.13293) 和 CADCrafter
  (https://arxiv.org/pdf/2504.04753) 的核心思路：

  真实图片 → (off-the-shelf模型) → 粗糙3D (point cloud / normal map)
                                            ↓
                       HoLa-BRep Point-Cloud Conditioned Diffusion

  具体做法：
  1. 用 TRELLIS (https://github.com/microsoft/TRELLIS)（Microsoft
  2025，rectified flow 架构，500K+ 3D assets 训练）或 InstantMesh
  从真实照片生成粗糙 mesh/point cloud
  2. 然后用你们论文里已经work的 point-cloud conditioned diffusion 来做 B-Rep
  生成

  优势：
  - 完全绕过了 image domain gap 问题——因为 point cloud 已经是 domain-invariant
  的
  - 你们论文里 point-cloud condition 的结果已经很好了
  - off-the-shelf 的 image-to-3D 模型已经很成熟

  方向5（长线，架构革新）：用 Flow Matching 替代 DDPM

  Rectified Flow / Flow Matching (https://arxiv.org/html/2512.13421v1) 相比
  DDPM：
  - 训练收敛更快（直线路径 vs 曲线路径）
  - 推理更少步数（5-10步 vs 20-50步）
  - 更稳定的梯度（更适合 conditional generation）

  TRELLIS (https://dgwave.net/blog/understanding-microsoft-trellis-3d-ai-model)
  就是用 rectified flow transformer 做的 3D generation。

  具体改动不大：把 DDPMScheduler 换成 flow matching objective：
  # DDPM: noise_input = alpha_t * x0 + sigma_t * eps
  # Flow matching: x_t = (1-t) * eps + t * x0
  # Loss: predict velocity v = x0 - eps

  方向6（如果坚持改 VAE）：参考 Img2CAD SIGGRAPH Asia 2025 
  (https://www.alphaxiv.org/overview/2410.03417) 的 Structured VLM Guidance

  如果你一定要改 VAE 端，更合理的方向是：
  - 不是加 learnable query（这破坏了原有 latent space 的结构）
  - 而是在 decode 阶段 加入图像条件引导
  - 具体：在 VAE decoder 的 face_attn2（第二个 12-layer
  transformer）里注入图像信息
  - 这样 VAE latent space 不变，但 decode 时有额外的 visual guidance

      """将真实照片的 DINOv2 特征映射到白模的 DINOv2 特征空间"""
      def __init__(self, dim=1024, depth=4):
          super().__init__()

                  d_model=dim, nhead=16, batch_first=True, norm_first=True))

          # 可选: residual connection 保留原始信息

      def forward(self, real_photo_features):

          mapped = self.mapper(real_photo_features)
          return real_photo_features + torch.sigmoid(self.gate) * (mapped -
  real_photo_features)

     Strategy A: Knowledge Distillation

     Teacher (frozen, white-model conditioned):
       white_render → DINOv2 → teacher_condition
       teacher.diffuse(noisy_z, t, teacher_condition) → teacher_pred

     Student (trainable, real-photo conditioned):
       real_photo → DINOv2 → student_condition
       student.diffuse(noisy_z, t, student_condition) → student_pred

     Loss = kd_w * MSE(student_pred, teacher_pred)
          + diff_w * MSE(student_pred, noise)
          + align_w * student_align_loss

  你面临的核心问题回顾

  白模图片 → DINOv2 → 特征A → Diffusion → 好的B-Rep ✓ (valid~0.82, Chamfer~0.15)
  真实照片 → DINOv2 → 特征B → Diffusion → 烂的B-Rep ✗ (valid~0.60, Chamfer~0.50)

  特征A ≠ 特征B。同一个物体，白模渲染提取的 DINOv2
  特征里几何信息充分；真实照片提取的特征里几何信息被纹理/背景/光影淹没了。

  你的 ControlNet
  实验已经证明：问题不在条件注入深度，而在特征本身缺乏精确几何信息。

  ---
  方法B：Feature Domain Mapper（推荐首选）

  一句话：训一个小网络，把"真实照片的DINOv2特征"翻译成"白模的DINOv2特征"。

  训练时：
    同一个物体 {
      真实照片 → DINOv2(frozen) → real_feat [B, 257, 1024]
      白模渲染 → DINOv2(frozen) → white_feat [B, 257, 1024]
    }
    mapper(real_feat) → mapped_feat
    Loss = MSE(mapped_feat, white_feat) + 0.5 * cosine_loss

  推理时：
    真实照片 → DINOv2 → mapper → "假装是白模特征" → 原来的Diffusion管线

  为什么可能有效：
  - 你已经有配对数据（FLUX.1-Kontext生成的，同一物体两种渲染）

  residual（初始化接近identity，逐渐学习delta）

  训练成本：很低。只训一个小transformer（~20M参数），几小时就够。

  上限：取决于"DINOv2特征之间的映射是否是可学习的"。如果两个域之间存在一个近似线
  性/非线性的对应关系，这就能work。如果对应关系太复杂（比如白模特征里有信息但真

● LTM3D 论文解读

  它要解决什么问题？

  3D 形状的条件生成（给一张图/一段文字 → 生成 3D）有两大类方法：

  方法: Diffusion (如你们的HoLa-BRep)
  优点: 擅长建模连续latent空间，生成质量高
  缺点: 条件对齐弱，不擅长建模token之间的结构依赖
  ────────────────────────────────────────
  方法: Auto-Regressive (如GPT风格)
  优点: 擅长建模序列依赖（token之间的关系）
  缺点: 逐个生成慢，误差累积

  LTM3D 的核心问题：能不能把两者的优势结合起来？用 AR 来建模 token
  之间的依赖关系，用 Diffusion 来建模每个 token 的分布。

  ---
  它的核心架构（三个组件）

  输入条件 (图片/文字)
        │
        ▼
  ┌─────────────────┐
  │  Prefix Learning │ ← 把条件"翻译"成形状空间的prefix tokens
  └────────┬────────┘
           │ prefix tokens T = [t₁, ..., t₆₄]
           ▼
  ┌─────────────────────────────────────────┐
  │  Conditional Distribution Modeling       │
  │                                          │
  │  for i = 1, 2, ..., n:                  │
  │    zᵢ = MAE(x<i, T)     ← AR部分：看前面的tokens │
  │    xᵢ ~ Diffusion(zᵢ)   ← Diffusion部分：生成当前token │
  │                                          │
  └─────────────────────────────────────────┘
           │
           ▼
  ┌──────────────────────────┐
  │  Latent Token Reconstruction │ ← 额外的"先验"指导
  └──────────────────────────┘
           │
           ▼
     3D Shape (SDF / PC / Mesh / 3DGS)

  ---
  组件1：Prefix Learning（条件对齐）

  问题：图片的 DINOv2 特征和 3D 形状的 latent token 不在同一个空间，怎么让
  condition 有效地指导生成？

  做法：
  # 64个可学习的 query 向量
  Q = nn.Parameter(torch.randn(64, 1024))

  # 用 cross-attention 从 condition 里"读取"信息
  T = FFN(CrossAttn(Q, C) + Q)
  # C = DINOv2(image) 或 CLIP(text)
  # T = [64, 1024] 的 prefix tokens，已经对齐到形状空间了

  关键insight：对齐发生在生成过程中而不是在编码阶段。这意味着同一套prefix
  learning可以适配不同的条件模态和不同的3D表示。

  对你的意义：这和你现在的 cross_attn_add_cond 做的事情类似——都是把 image tokens
   转换为 shape-aligned 的 tokens。但 LTM3D 用的是 learnable queries 而不是
  noisy latent 作为 query，这可能更稳定。

  ---
  组件2：MAE + Diffusion（核心生成）

  核心公式：
  p(X|T) = ∏ᵢ p(xᵢ | x<i, T)

  把联合分布分解为自回归的形式：第 i 个 token 的分布取决于前面所有 tokens +
  prefix。

  具体做法：

  1. MAE（Masked AutoEncoder）：16层encoder + 16层decoder
    - 输入：前 i-1 个已生成的 tokens + prefix tokens T
    - 输出：一个 context vector zᵢ，编码了"前面的结构信息"
    - 训练时随机 mask 70-100% 的 tokens（类似 BERT）
  2. DenoiseNet（小型 Diffusion）：8层 MLP
    - 输入：context zᵢ + timestep t
    - 输出：预测噪声 ε
    - 生成第 i 个 token 的具体值

  直觉：MAE 负责"看前面的结构，决定下一个 token
  应该大致是什么"（结构依赖），DenoiseNet
  负责"在这个约束下，生成精确的数值"（连续分布）。

  ---
  组件3：Reconstruction-Guided Sampling (RGS)

  问题：AR 采样是逐步的，早期错误会累积。

  解决：训一个独立的"重建网络"，直接从 condition 预测所有 tokens 的粗糙估计：

  # 重建网络：1层cross-attn + 24层self-attn
  X_hat = SelfAttn(CrossAttn(Q_shape, C) + Q_shape)  # 直接预测所有tokens

  采样时混合：
  # 前30步：混入重建结果作为"先验"
  x_blend = 0.9 * x_reconstructed + 0.1 * x_sampled   # 前30步
  x_blend = x_sampled                                    # 30步之后

  直觉：重建网络给了一个"大致正确的方向"（确定性的），AR+Diffusion
  在此基础上做精细调整（随机性的）。类似于"先画草稿再细化"。

  ---
  为什么它和你的问题相关？

  LTM3D 里有两个 idea 可以借鉴到你的工作中：

  1. Prefix Learning → 替代你现在的 cross_attn_add_cond

  你现在的做法：noisy latent 作为 query，cross-attend 到 image tokens。

  LTM3D 的做法：固定的 learnable queries 作为 query，cross-attend 到
  condition，输出作为 prefix 拼在 latent 前面。

  差异：LTM3D 的 prefix 不依赖于 noisy latent（更稳定），而是纯粹从 condition
  中提取结构信息。

  你可以尝试：把 cross_attn_add_cond 改成 prefix 风格：
  # 现在：noisy_latent attend to image
  cad_tgt = proj(noisy_features)
  output = cross_attn(tgt=cad_tgt, memory=img_memory)

  # LTM3D 风格：learnable queries attend to image, 输出拼在前面
  prefix_queries = nn.Parameter(torch.randn(8, 1024))
  prefix = cross_attn(tgt=prefix_queries, memory=img_memory)
  noise_features = torch.cat([prefix, noise_features], dim=1)  # 拼接
  # 然后 self-attention backbone 会同时看到 prefix 和 noisy tokens

  2. Reconstruction-Guided Sampling → 结合你的 Feature Mapper

  LTM3D 训了一个独立的网络直接从 condition 预测所有 latent
  tokens（粗糙估计），然后用这个粗糙估计来"引导"diffusion 采样。

  对你的启发：你可以训一个简单的回归网络：
  image_features → 粗糙估计的 face_z [30, 32]
  然后在 diffusion inference 时，不从纯噪声开始，而是从这个粗糙估计加噪声开始：
  # 原来：从纯噪声开始
  x_T = torch.randn(B, 30, 32)

  # 改进：从粗糙估计开始（加部分噪声）
  x_coarse = regression_net(image_features)  # 粗糙预测
  x_T = scheduler.add_noise(x_coarse, noise, t=800)  # 只走最后800步

  这本质上是缩短了 diffusion 
  需要走的距离——不需要从纯噪声走到目标，只需要从"大致正确"走到"精确"。

  ---
  总结

  LTM3D 组件: Prefix Learning
  做什么: 条件→形状空间的可学习桥梁
  对你的借鉴意义: 替代/增强你的 cross_attn_add_cond
  ────────────────────────────────────────
  LTM3D 组件: MAE + Diffusion
  做什么: AR建模token依赖 + Diffusion建模分布
  对你的借鉴意义: 你的场景可能不需要AR（face tokens间无明显顺序）
  ────────────────────────────────────────
  LTM3D 组件: Reconstruction-Guided Sampling
  做什么: 粗糙估计引导精细采样
  对你的借鉴意义: 最有价值：直接回归一个初始估计，减少diffusion步数

  如果我是你，我最想从这篇论文里借鉴的是 RGS 的思想——训一个小网络直接从 image
  feature 回归出粗糙的 face latents，然后让 diffusion 从这个"warm
  start"开始而不是从纯噪声开始。这可以和你的 Feature Mapper 或 Knowledge
  Distillation 结合使用。

● 关于 VAE 的改进建议

  你指出的问题确实是关键痛点

  问题: Conv2D grid 编码
  具体表现: 依赖固定 16×16 分辨率
  根因: 空间归纳偏置太强，对曲面参数化敏感
  ────────────────────────────────────────
  问题: Random padding
  具体表现: 不足 30 面时随机复制填充到 30
  根因: Diffusion 需要固定长度输入
  ────────────────────────────────────────
  问题: 去重依赖经验阈值
  具体表现: distance < 1e-2 hardcoded
  根因: 推理时没有"哪些是真实face"的信号
  ────────────────────────────────────────
  问题: Valid rate 和 F1 受去重影响大
  具体表现: 阈值稍变，结果就变
  根因: 生成的 latent 不天然具备"一个token一个face"的语义

  你之前 3DShape2VecSet 的尝试为什么失败

  你说你在 encoder 末尾 加了 learnable query cross-attention，把 [B, face_num, 
  32] → [B, 30, 32]。

  失败原因：你破坏了 decoder 期望的语义结构。

  原来：latent[i] = 第i个face的编码 → decoder[i] = 重建第i个face
  你改后：latent[i] = 某种全局混合 → decoder[i] = ??? 不知道该重建什么

  HoLa-BRep 的 decoder 是 per-face 的：每个 latent vector 独立过
  face_points_decoder 重建一个面。如果 latent 不再有 per-face 语义，decoder
  就崩了。

  3DShape2VecSet 能 work 是因为它的 decoder 也是 query-based 的（用坐标 query 出
   SDF/occupancy），不需要 latent token 有明确的 part 对应关系。你们的 decoder
  需要。

  你之前的尝试方向错了（在encoder末尾加query），但 3DShape2VecSet
  的思想可以用在另一个地方——diffusion 侧：

  # 不改 VAE，改 diffusion 的 latent 表示方式
  # 原来：diffusion 直接生成 [30, 32] 的 face features
  # 改进：diffusion 生成一个"shape-level latent set" [K, D]
  #       然后用一个 decoder 把 set → per-face features

  # Diffusion 生成：
  shape_set = diffusion.sample()  # [B, K, D], K=16, D=128

  # Set → Faces decoder（新增模块）：
  face_queries = learnable_queries(30)  # 或动态数量
  face_features = cross_attn(face_queries, shape_set)  # [B, 30, 32]

  # 然后正常 VAE decode
  result = vae.decode(face_features)

  这样：
  - VAE 不变（per-face 语义保留）
  - Diffusion 生成的是一个更紧凑的、shape-level 的 set
  - 从 set 到 per-face 的展开由一个可学习的 decoder 完成
  - 这个 set-to-faces decoder 可以学到 deduplication 的逻辑

  这个思路本质上是把 "面数量预测" 和 "面特征生成" 解耦了——diffusion
  只管生成一个紧凑的 shape representation，不用操心具体有几个面。

  ---
  在 HoLa-BRep 上做"拓扑引导"的三种方案

  你现在的问题

  当前 HoLa-BRep 的生成流程：

  Diffusion → face_z [30, 32] → Decoder {
      1. face_points_decoder(face_z)     → 几何 ✓
      2. face_z[i] ⊕ face_z[j] → AttnIntersection → 预测是否相邻  →
  拓扑（后补的）
  }

  问题：拓扑完全依赖 face_z 里"隐含"的信息。
  如果 diffusion 生成的 face_z 几何对了但拓扑信息弱 → valid rate 低。

  方案1：最小改动 —— Topology Attention Bias（推荐先试）

  核心思想：从 image condition 预测一个"哪些面应该相邻"的先验，注入 diffusion
  backbone 的 self-attention。

  Image → TopologyPredictor → adj_matrix [30, 30]（0~1概率）
                                      ↓
  Diffusion Backbone (24-layer Transformer):
      self_attention(Q, K, V):
          attn_weights = Q @ K^T / sqrt(d)
          attn_weights += topology_bias(adj_matrix)  ← 新增！
          attn_weights = softmax(attn_weights)

  为什么有效：
  - 相邻面的 latent 应该相互参考（它们共享边、需要几何连续）
  - 现在的 self-attention 对所有 face pairs 一视同仁
  - 加了 topology bias 后，相邻面的注意力权重增大 → latent
  之间的信息流更符合拓扑结构

  改动量：~50行代码，不改 VAE，不改 latent space。

  我已经写好了 models/topology_guided.py 里的 TopologyPredictor +
  TopologyAttentionBias。

  ---
  方案2：Disentangled Latent —— 把 latent 拆成 [拓扑 | 几何]

  核心思想：把每个 face 的 32维 latent 明确分成两部分：

  face_z = [topo_z (16维) | geom_z (16维)]

  topo_z: 编码这个面"和谁相邻、在整体结构中的角色"
  geom_z: 编码这个面"具体的曲面形状"

  训练时加辅助 loss 保证解耦：
  - topo_z 单独就能预测 adjacency → topo_classifier_loss
  - geom_z 单独就能重建 face points → geom_recon_loss

  Diffusion 侧：可以两阶段生成：
  Phase 1: 从噪声生成 topo_z（前16维），conditioned on image
  Phase 2: 从噪声生成 geom_z（后16维），conditioned on image + topo_z

  好处：
  - Phase 1 出来后，你已经"大致确定了拓扑结构"
  - Phase 2 在拓扑约束下生成几何，更容易做对

  所以这个 32 维 latent 的实际含义是：

  class AutoEncoder_1119_WithTopo(AutoEncoder_1119):

          self.topo_encoder = nn.Sequential(

              nn.LeakyReLU(),
              nn.Linear(self.df, self.topo_dim * 2),  # mean + logvar

  ✅ 做法C：通道级解耦（在 2×2 空间内，按 channel 分工）

  不改维度总数，但鼓励不同 channel 编码不同类型的信息：

  8 channels × 2×2:
    Channel 0-3: 主要编码面的几何形状（局部曲率、朝向）
    Channel 4-7: 主要编码面的拓扑角色（边界特征、相邻关系）

  通过 loss 设计来隐式鼓励：
  # face_z reshape 为 [N, 8, 2, 2]
  # 几何 loss 只对 channel 0-3 有梯度
  geom_z = face_z[:, :4, :, :]  # [N, 4, 2, 2] = 16维
  # 拓扑 loss 只对 channel 4-7 有梯度  
  topo_z = face_z[:, 4:, :, :]  # [N, 4, 2, 2] = 16维

  loss_geom = reconstruct(geom_z)  # 只用 channel 0-3 重建几何
  loss_topo = adjacency_predict(topo_z)  # 只用 channel 4-7 预测拓扑

  ✅ 做法D：完全不改 VAE，只改 Diffusion 的生成顺序

  最 pragmatic 的方案：

  保持 VAE 和 latent 不变。只修改 diffusion inference 策略：

  # 标准 DDPM: 从纯噪声 x_T 出发，逐步去噪 1000 步

  # 改进: "拓扑优先去噪"
  # 前 500 步: 让 attention bias 强烈倾向拓扑正确性
  # 后 500 步: 逐渐放松，专注几何精度

  for t in scheduler.timesteps:
      # 动态调整 topology bias 强度
      topo_weight = 1.0 if t > 500 else (t / 500)  # 前期强，后期弱

      attn_bias = topo_weight * topology_attention_bias(adj_pred)
      pred = model.diffuse(noisy, t, condition, attn_bias=attn_bias)
      noisy = scheduler.step(pred, t, noisy)

  直觉：生成过程的早期（高噪声时）决定了整体结构/拓扑，后期（低噪声时）精修几何
  细节。在早期给强拓扑引导，后期让模型自由精修几何。

  先做一个诊断实验

  在改 VAE 之前，先跑这个测试：

  # 这告诉你 VAE 本身能重建多好

  # 如果 VAE 重建的 Chamfer 很小（< 0.001）→ VAE 没问题，是 diffusion 的问题

  从你 EXPERIMENT_RECORD 里的 E5 数据看，面数正确时 valid rate = 0.89，说明 VAE
  decode 能力本身不差。问题更多在 diffusion 生成的 latent 不在 VAE
  能正确解码的区域内。

  VAE 的三个可改方向

  方向A：让 latent space 更"generation-friendly"

  问题：KL weight = 1e-6，几乎是 AE 不是 VAE。latent space 不够 regular。

  改进：
  - 增大 KL weight（1e-4 ~ 1e-3），让 latent 更接近标准正态分布
  - 代价：重建质量会下降
  - 权衡：用 KL annealing（前期低KL学好重建，后期逐渐增大KL正则化空间）

  # KL Annealing schedule
  kl_weight = min(target_kl_weight, current_step / warmup_steps *
  target_kl_weight)

  为什么这对 diffusion 有帮助：Diffusion 假设 latent 是高斯分布（从 N(0,1)
  开始去噪）。如果 VAE 的 latent 分布很不规则（因为 KL 太小），diffusion
  在训练分布边缘采到的点 decode 出来就是垃圾。

  方向B：换编码架构（TokenVAE 或 Perceiver-style）

  问题：Conv2D 16×16 → 2×2 压缩太猛，且依赖参数化网格。

  改进选项：

  方案: TokenVAE (你已有代码)
  架构: Learnable queries cross-attend to point grid
  好处: 不依赖固定分辨率
  ────────────────────────────────────────
  方案: Perceiver-style
  架构: 一组固定 latent tokens 迭代 cross-attend
  好处: 更灵活的压缩比
  ────────────────────────────────────────
  方案: Hybrid
  架构: Conv 初步压缩 + Token 精修
  好处: 兼顾效率和表达力

  关键实验：TokenVAE 里 num_tokens 的影响
  - 当前默认 k=4 → 每个 face 用 4 个 token 表示 → 压平为 4×(32/4)=32 维
  - 试试 k=8 或 k=16 → 更多 token → 更丰富的表达
  - 但 latent 维度会变（k=8 → 还是 32 维？还是 64 维？取决于 token_dim 设置）

  方向C：VAE + Diffusion 联合训练（最激进）

  问题：当前是两阶段分离训练（先训 VAE → 冻住 → 训 diffusion）。VAE 不知道下游
  diffusion 会怎么用它的 latent。

  改进：End-to-end latent diffusion training
  - 不冻住 VAE，同时训 VAE 重建 loss + diffusion loss
  - VAE 会自适应地学到"对 diffusion 友好"的 latent 结构

  参考：
  - Latent Diffusion Model (Rombach 2022) (https://arxiv.org/abs/2112.10752) —
  虽然他们也是分阶段，但讨论了 KL 正则化对下游的重要性
  - D-Flow (2025) (https://arxiv.org/abs/2501.09879) — 改进 VAE 使其更适合
  flow-based 生成
  - REPA (2025) (https://arxiv.org/abs/2410.06940) — Representation Alignment 让
   VAE latent 对齐外部表示

  │          Loss          │ Conv VAE (原版) │ Token VAE (全替换) │  变化  │

  为什么会这样？

  这个现象完全可以解释：

  Token-based（attention）擅长什么：全局关系、结构理解、相对位置
  - edge_classification = "这两个面之间有没有边" → 全局拓扑关系 → ✓
  attention擅长
  - edge_feature = "边的特征和面对关系对不对" → 关系匹配 → ✓
  - face_bbox = "面的中心和缩放" → 全局位置信息 → ✓

  Token-based（attention）不擅长什么：精确的局部空间连续性
  - face_coord = "16×16 网格上每个点的精确 xyz 坐标" → 局部空间平滑性 → ✗
  - edge_coord = "16个采样点的精确位置" → 序列上的空间连续性 → ✗

  核心原因：

  Conv2D/Conv1D
  有天然的局部平滑归纳偏置——相邻像素/采样点一起卷积处理，输出自然平滑。

  Token decoder（SurfaceQueryDecoder）是这样工作的：
  # 对每个 UV 查询点独立地 cross-attend 到 latent tokens
  for each (u, v) in 16×16 grid:
      point[u,v] = cross_attention(query=PE(u,v), key=latent_tokens,
  value=latent_tokens)

  每个点是独立查询的！ 没有任何机制保证相邻 UV 点的输出是平滑的。结果就是重建的
  面"坑坑洼洼"——每个点各自为政，不像一个光滑曲面。

  ---
  为什么 TokenEnc + ConvDec（你的代码里 
  AutoEncoder_1119_TokenEncConvDecVAE）也不好？

  因为问题出在编码端：

  Conv encoder:  [N, 6, 16, 16] → [N, 8, 2, 2]
                  ↑ 保留了空间结构！2×2 的每个位置对应面的一个象限

  Token encoder: [N, 6, 16, 16] → learnable queries → flatten → [N, 32]
                  ↑ 32维没有空间含义了！只是一组抽象特征

  然后 Conv decoder 做 Rearrange([32] → [8, 2, 2]) → ConvTranspose2d，但这个 [8,
   2, 2] 是假的——它已经不代表空间象限了，只是被强行 reshape。Conv decoder
  的空间上采样假设破了。

  ---
  正确的改进方向

  既然问题清楚了——token 好在结构理解，conv 好在空间精度——那解决方案也清楚了：

  方案：不要动 encoder/decoder 的点重建部分，只改 latent fusion 部分

  回看你的 VAE pipeline：

  face_coords (Conv2D)     → face_features [N, 32]     ← 这个保留！空间精度好
  edge_coords (Conv1D)     → edge_features [N, 64]     ← 这个保留！
           ↓
  face_attn (Transformer)  → 加上 inter-face 信息       ← 这里已经是 attention
  了
  GAT (GATv2Conv)          → 加上 edge-based 拓扑信息   ← 这里已经有图结构了
  global_feature           → 加上全局信息
           ↓
  gaussian_proj            → face_z [N, 32]
           ↓
  face_attn2 (Transformer) → 解码前的 inter-face 交互    ← 这里也是 attention
  face_points_decoder (ConvTranspose2d) → 重建            ← 这个保留！

  你的 VAE 已经是 hybrid 了！ Conv 处理局部空间精度，Transformer+GAT
  处理全局结构/拓扑。

  所以不应该替换 Conv 部分，而应该：

  1. 加强中间的 attention/graph 部分（已经存在，可以加深/加宽）
  2. 改 latent 正则化（KL weight）
  3. 改 padding 策略（zero-pad + classifier）

  ---
  关于 Addition Tag 失败

  为什么必然失败：

  Diffusion 模型的核心假设是 latent 服从连续分布。它从 N(0,1)
  开始做连续变换到目标分布。

  但 tag 是离散的 (+1 或 -1)。你让 diffusion 同时生成连续的 face_z 和离散的
  tag，它做不好。中间步骤里 tag 会是 0.3、-0.7 这种不伦不类的值。

  正确做法：tag 不应该由 diffusion 生成。应该：
  - 方案1：Diffusion 生成连续 latent → 后接一个 classifier 判断
  keep/drop（你现在 pad_method="zero" 就是这个逻辑）
  - 方案2：先预测面数 → diffusion 只生成那么多 token

  ---
  修正后的 VAE 改进方向

  方向: KL sweep
  做什么: 调 gaussian_weights: 1e-4, 1e-3
  不做什么: 不改架构
  ────────────────────────────────────────

  绝对不要做的：

  正确的思路：
  - ✅ Conv 负责"局部精确重建"（它已经很好了）
  - ✅ Attention/Graph 负责"全局结构和拓扑"（可以加强）
  - ✅ KL 正则化负责"让 latent space 对 diffusion 友好"
  - ✅ Classifier/Predictor 负责"面数判断"（不混进 diffusion 的连续生成中）

  VAE 到底在干什么

  先忘掉一切术语，用最简单的语言描述整个系统：

  你有一个 CAD 模型（比如一个杯子），它由若干个"面"组成（杯壁、杯底、把手...）

  每个面 = 一个 16×16 的点阵（256个3D坐标点，描述这个曲面的形状）

    把每个面的 256 个点 压缩成 32 个数字

  现在的问题出在哪？

  问题1：KL weight = 1e-6（最核心）

  VAE 训练时的 loss:

  total_loss = reconstruction_loss + 0.000001 * KL_loss
               ├── face coord重建         ├── 让latent接近N(0,1)
               ├── edge coord重建         │
               ├── edge classification    │
               └── ...                    └── 几乎等于 0，不起作用！

  结果：VAE 为了重建质量把 latent 编码到一个非常"紧凑"的区域：

  想象 latent space 是一个房间(32维):

  KL 大 (1e-2):                    KL 小 (1e-6, 现在):
  ┌─────────────────┐              ┌─────────────────┐
  │ ○ ○  ○ ○  ○ ○  │              │                 │
  │  ○ ○  ○ ○  ○   │              │                 │
  │ ○  ○ ○  ○ ○ ○  │              │    ·····        │
  │  ○ ○ ○  ○  ○   │              │    ····         │ ← 所有数据挤在一小团
  │ ○ ○  ○  ○ ○ ○  │              │    ····         │
  │  ○ ○ ○ ○ ○  ○  │              │                 │
  └─────────────────┘              └─────────────────┘
    均匀分布                          集中在小区域
    diffusion容易生成                  diffusion必须精确命中这团

  Diffusion 的工作：从整个房间的随机位置 N(0,1) 出发 → 走到有效数据的位置。

  - 如果数据散布在整个房间（KL大）→ diffusion 容易走对
  - 如果数据挤在一个角落（KL小）→ diffusion 稍有偏差就走到"空白区域" → VAE
  decode 出垃圾

  白模条件时还行，是因为白模的 DINOv2 特征和 latent 分布高度相关，condition
  能精确引导 diffusion 到那个角落。

  真实照片时不行，是因为真实照片的 DINOv2 特征噪声大，condition
  引导不够精确，diffusion 偏到那团旁边 → decode 出垃圾。

  修复：增大 KL weight → 强制 latent 分布更接近 N(0,1) → diffusion
  的容错空间变大。代价是重建质量会下降（latent
  被"压扁"了，信息损失），需要找一个平衡点。

  ---
  问题2：Random Padding + Dedup

  一个 8 面的物体，训练时：
    真实 latent: [z1, z2, z3, z4, z5, z6, z7, z8]
    padding后:   [z1, z2, z3, z4, z5, z6, z7, z8, z3, z5, z1, z7, z2, z8, z4,
  z6,
                  z1, z3, z8, z5, z2, z7, z4, z6, z1, z3, z5, z2, z7, z4]
                                                      ↑ 随机复制填满30个

  Diffusion 学到的是: "生成30个东西，有些会重复"

  推理时：
  Diffusion 生成 30 个 latent → 哪些是"真的"？
    ↓
  去重: 两两比较距离，distance < 0.01 的认为是重复 → 删掉
    ↓
  问题: 0.01 这个阈值从哪来？不同物体适用不同阈值吗？

  你的 E5 实验已经证明：
  - 面数猜对了 → valid rate 89%
  - 面数猜多了 → valid rate 24%
  - 面数猜少了 → valid rate 38%

  修复：用 zero-padding + classifier
  训练时:  [z1, z2, ..., z8, 0, 0, 0, ..., 0]  ← 后面22个全是0
                            │
  Classifier 学: 非零=真实面, 零=空位

  推理时: Diffusion 生成30个 → classifier 判断每个是不是真的 → 只保留"真的"

  这比去重更干净——classifier 直接告诉你答案，不需要经验阈值。

  ---
  问题3：Conv2D 编码器（优先级最低）

  这个前面已经分析清楚了——Conv2D 的空间重建能力很好（你的重建 CD 是
  0.001~0.01），目前不是瓶颈。

  ---
  所以 VAE 改进的本质是什么？

  一句话：让 VAE 的 latent space 对 diffusion 更"友好"。

  不是让 VAE 重建更好（它已经够好了），而是让 diffusion
  在这个空间里更容易生成正确的东西。

  类比：
  - VAE 是一个翻译官（中文 ↔ 英文）
  - Diffusion 是一个写作者（在英文空间里写作）
  - 现在翻译官把所有有效的中文意思压缩到了英文的一小撮词里
  - 写作者必须精确用这几个词才能写出正确的句子
  - 改 KL = 让翻译官用更广泛的英文词汇 → 写作者更容易写对
  - 改 padding = 让写作者不用猜"我应该写多少句话" → 有明确信号告诉他停

  这就是 VAE 改进计划里在做的全部事情。每一步都不是在让 VAE 重建更好，而是在让
  diffusion 的工作更容易。

  关于 VAE 的更深层改进思考

  你问的是：对于 B-Rep/CAD 模型，现在的 VAE 理解上还有什么不足？

  B-Rep 不是普通的 3D 形状

  B-Rep 区别于 mesh/点云/SDF 的核心特征：

  特性: 面的参数化连续性
  B-Rep 有，mesh/点云没有: 每个面是一张光滑曲面（C²连续）
  当前 VAE 是否捕捉到？: ✓ Conv2D在UV网格上天然平滑
  ────────────────────────────────────────
  特性: 边的精确共享
  B-Rep 有，mesh/点云没有: 两个相邻面必须在共享边上完全重合
  当前 VAE 是否捕捉到？: △ 只通过 loss 软约束，不是硬保证
  ────────────────────────────────────────
  特性: 拓扑合法性
  B-Rep 有，mesh/点云没有: 必须构成 2-manifold（闭合壳体）
  当前 VAE 是否捕捉到？: ✗ 后预测拓扑，无保证
  ────────────────────────────────────────
  特性: 几何-拓扑一致性
  B-Rep 有，mesh/点云没有: 面的形状必须和拓扑结构一致
  当前 VAE 是否捕捉到？: △ GAT传递拓扑信息，但是隐式的
  ────────────────────────────────────────
  特性: 边界约束
  B-Rep 有，mesh/点云没有: 面的边界必须和边的几何完全吻合
  当前 VAE 是否捕捉到？: ✗ 面和边独立decode，靠后处理对齐

  当前 VAE 的真正不足（不是 Conv2D 的问题）

  不足1：面和边的解码是独立的，没有几何一致性约束

  当前：
    face_z → face_points_decoder → face 上的点
    face_pair_z → inter → edge_feature → edge_points_decoder → edge 上的点

  问题：face 的边界点 和 edge 的点 理论上应该完全重合
       但它们是各自独立 decode 的，只通过 loss 软约束
       → post-processing 里的 geometry_optimization 就是在修补这个 gap

  如果能在 decode 时就保证一致性，post-processing 的负担会大幅减轻，valid rate
  也会提升。

  参考做法（DTGBrepGen 的思路）：
  - 先 decode vertex 坐标（面和边的交点）
  - Edge 的形状 = 连接两个 vertex 的曲线（受 vertex 约束）
  - Face 的形状 = 被若干 edge 围成的曲面（受 edge 约束）
  - 层层约束，几何一致性是构造性的而不是loss监督的

  不足2：拓扑是后预测的，不参与几何生成

  当前：
    Diffusion 生成 face_z → Decoder 先重建面 → 然后预测哪些面相邻

  问题：面的形状 不知道 它最终会和谁相邻
       → 可能生成了两个面，形状上本该共享一条边，但因为不知道这个约束
         所以两个面的边界各自随意 → post-processing 要硬掰过来

  如果拓扑信息在 decode 之前就已知，decoder 可以利用它来保证相邻面在边界上一致。

  这就是我之前说的 Topology Attention Bias 的动机——不是改 VAE 架构，而是在
  diffusion 阶段给拓扑先验，让生成的 face_z 本身就"知道"自己的拓扑角色。

  不足3：每个面的 latent 维度可能不够表达复杂曲面

  32 维 = 8 channels × 2×2

  对于简单面（平面、圆柱面）：32维足够
  对于复杂面（freeform B-spline，高曲率变化）：32维可能欠拟合

  但你的重建 CD 是 0.001~0.01，说明对当前数据集这个维度够用。如果未来换更复杂的
  数据集可能需要增加。

  拓扑引导 Diffusion 的具体做法

  核心思路

  推理时：
    真实照片 → TopologyPredictor → "第3面和第7面应该相邻" (adj matrix)
                                           ↓
    Diffusion 的 self-attention:
      原来:  attention(token_i, token_j) 对所有 (i,j) 一样
      现在:  attention(token_i, token_j) + bias(i,j)
             其中 bias(i,j) > 0 如果 i,j 应该相邻
                  bias(i,j) < 0 如果 i,j 不相邻

  效果：相邻面的 token 互相"拉扯"，生成的 latent 自然更一致。类似于 encoder 里
  GAT 的作用，但在生成端。

  具体实现步骤

  Step 1：训一个 TopologyPredictor

  这是一个很简单的网络，从 condition（图片特征）预测邻接矩阵：

  class TopologyPredictor(nn.Module):
      """
      从图片 DINOv2 特征预测：30个面之间哪些应该相邻。
      输出: [B, 30, 30] 的概率矩阵
      """
      def __init__(self):
          super().__init__()
          # 全局特征 [B, 257, 1024] → pool → [B, 1024]
          self.pool = nn.Sequential(
              nn.Linear(1024, 512),
              nn.GELU(),
          )
          # 预测 30×30 的邻接概率
          self.pred = nn.Sequential(
              nn.Linear(512, 512),
              nn.GELU(),
              nn.Linear(512, 30 * 30),
          )

      def forward(self, img_features):
          x = img_features.mean(dim=1)  # [B, 1024] → pool
          x = self.pool(x)
          adj = self.pred(x).reshape(-1, 30, 30)
          adj = (adj + adj.transpose(-1, -2)) / 2  # 对称化
          return torch.sigmoid(adj)  # [B, 30, 30] 每个值 0~1

  训练数据：你已有的缓存数据里就有 GT adjacency。训练目标就是 BCE(pred_adj,
  gt_adj)。

  这个网络非常小，训练很快（几分钟到几十分钟）。它的精度不需要100%——即使是"大致
  正确"的拓扑先验也有用。

  ---
  Step 2：把邻接矩阵变成 Attention Bias

  def topology_to_attention_bias(adj_prob, scale=2.0):
      """
      把 [B, 30, 30] 的邻接概率转成 attention logit bias。
      
      相邻面 → 正 bias（增加attention weight）
      不相邻 → 负 bias（减少attention weight）
      """
      # logit 形式: log(p / (1-p))
      bias = torch.log(adj_prob + 1e-6) - torch.log(1 - adj_prob + 1e-6)
      return bias * scale  # [B, 30, 30]

  Step 3：注入到 Diffusion backbone 的 self-attention

  现在你的 net1 是一个 24 层 TransformerEncoder，它的 self-attention 计算：

  # 标准 self-attention:
  attn_weights = Q @ K^T / sqrt(d)  # [B, num_heads, 30, 30]
  attn_weights = softmax(attn_weights)
  output = attn_weights @ V

  加入 topology bias 后：

  # 修改后的 self-attention:
  attn_weights = Q @ K^T / sqrt(d)           # [B, num_heads, 30, 30]
  attn_weights = attn_weights + topo_bias     # ← 加上拓扑先验！
  attn_weights = softmax(attn_weights)
  output = attn_weights @ V

  这意味着：如果 TopologyPredictor 说 face_3 和 face_7
  应该相邻（adj[3,7]=0.9），那么在 self-attention 中 face_3 会更多地关注 face_7
  的信息（反之亦然）。

  这模拟了 encoder 中 GAT 沿着边传递信息的效果——但在生成端。

  ---
  Step 4：Timestep-dependent 强度调度

  直觉：
  - 高噪声阶段（t=1000~500）：确定整体结构/拓扑，bias 要强
  - 低噪声阶段（t=500~0）：精修几何细节，bias 要弱（避免过度约束）

  def get_topo_bias_weight(timestep, schedule="cosine"):
      """高噪声时强引导，低噪声时弱引导"""
      t_normalized = timestep / 1000.0  # 归一化到 [0, 1]
      if schedule == "cosine":
          return 0.5 * (1 + math.cos(math.pi * (1 - t_normalized)))
      elif schedule == "linear":
          return t_normalized
      elif schedule == "step":
          return 1.0 if t_normalized > 0.5 else 0.0

  完整推理流程

  @torch.no_grad()
  def inference_with_topology(model, topo_predictor, image_features, device):
      # 1. 预测拓扑
      adj_prob = topo_predictor(image_features)  # [B, 30, 30]
      topo_bias = topology_to_attention_bias(adj_prob)  # [B, 30, 30]

      # 2. 正常 diffusion 初始化
      face_z = torch.randn(B, 30, 32, device=device)

      # 3. 去噪循环
      for t in scheduler.timesteps:
          # 动态调整 bias 强度
          weight = get_topo_bias_weight(t)
          current_bias = topo_bias * weight

          # Diffusion 一步（传入 topology bias）
          pred = model.diffuse(face_z, t, condition, attn_bias=current_bias)
          face_z = scheduler.step(pred, t, face_z).prev_sample

      return face_z

          # 或者替换为自定义 attention
          output = layer(output, src_mask=attn_bias)  # additive mask
      return output

  注意：PyTorch 的 nn.TransformerEncoderLayer 的 src_mask 参数是 additive 
  mask（加到 attention logits 上），正好就是我们要的！所以改动非常小——只需要把
  topo_bias 传进去就行。

  ---
  为什么这比直接加条件注入有效？

  你试过的：ControlNet（每层都注入 image condition）→ valid rate↑ 但 Chamfer
  不动
            原因：image condition 不包含精确几何信息

  Topology Bias 不同：
    它不是在告诉 diffusion "生成这个形状"
    而是在告诉 diffusion "不管你生成什么形状，这些面之间要一致"

    它是一个 结构约束，不是几何约束
    它解决的是 "面之间关系的一致性" 而不是 "每个面的具体形状"

  它和 Feature Mapper 是正交的：
  - Feature Mapper 解决："让 diffusion 知道要生成什么形状"（几何引导）
  - Topology Bias 解决："让 diffusion 知道各面之间的关系"（结构引导）
  - 两者叠加可能同时改善 Chamfer 和 F1

  Decoder 的问题

  Decoder:
    face_z [N, 32]
       ↓
    face_attn2 (12层 Transformer) — 面之间互相看
       │
       │  ⚠️ 问题1: 推理时 attn_mask = 全零（所有面平等对待）
       │            没有拓扑结构告诉它谁和谁真正相邻

       │

       │                          ↑ 独立decode，不知道自己的边长什么样
       │
       └── face_pair → AttnIntersection → edge_feature
                                                │
                                                ├── classifier → 有没有边
                                                └── edge_points_decoder →
  边的坐标 [E, 16, 6]
                                                      ↑
  独立decode，不知道相邻面长什么样

  两个核心问题：

  问题1：face_attn2 推理时没有拓扑信息

  训练时 encoder 有 GAT 融合拓扑 → face_z 已经有拓扑信息了，所以 face_attn2
  即使没有显式拓扑也能凑合工作（face_z 本身 "记得" 自己的邻居）。

  但推理时，face_z 是 diffusion 生成的，不保证"记得"正确的邻居关系。face_attn2
  用 all-to-all attention 处理，没有拓扑引导 → 可能把不相邻的面特征混在一起。

  问题2：面和边的几何独立 decode

  face_points = face_points_decoder(face_z')     ← 面自己decode自己的
  edge_points = edge_points_decoder(edge_feature) ← 边自己decode自己的

  面在边界处的点  ≠  边上的点  （理论上应该完全相等！）

  这导致后处理（geometry_optimization.py）里要花大量计算把它们"掰"到一起。如果
  decode 时就能保证一致性，后处理会容易得多，valid rate 也会更高。

  ---
  三种改法（从简单到复杂）

  改法1：加一个 Boundary Consistency Loss（最简单，不改架构）

  思路：不改任何网络结构，只加一个 loss 告诉 VAE "面的边界要和边的几何一致"。

  def boundary_consistency_loss(face_points, edge_points,
  edge_face_connectivity):
      """
      面在边界处的点 应该 = 对应边上的点。
      
      face_points: [N, 16, 16, 3] — 每个面的 16×16 点阵
      edge_points: [E, 16, 3] — 每条边的 16 个点
      edge_face_connectivity: [E, 3] — (edge_id, face_i, face_j)
      """
      loss = 0
      for e_idx in range(edge_points.shape[0]):
          edge_pts = edge_points[e_idx]  # [16, 3]
          face_i = face_points[edge_face_connectivity[e_idx, 1]]  # [16, 16, 3]
          face_j = face_points[edge_face_connectivity[e_idx, 2]]  # [16, 16, 3]

          # 面的边界 = 16×16 网格的四条边 (第0行/最后一行/第0列/最后一列)
          # 找和 edge_pts 最近的边界
          boundaries_i = torch.cat([
              face_i[0, :, :],   face_i[-1, :, :],
              face_i[:, 0, :],   face_i[:, -1, :],
          ], dim=0)  # [64, 3]

          # Edge 上每个点到 face 边界最近的距离
          dist_i = torch.cdist(edge_pts.unsqueeze(0),
  boundaries_i.unsqueeze(0)).squeeze()
          loss += dist_i.min(dim=1)[0].mean()

      return loss / edge_points.shape[0]

  改动量：只在 loss() 函数里加几行。VAE 在训练时就会学到"decode
  出来的面边界要和边吻合"。

  ---
  改法2：Topology-Aware face_attn2（推理时用预测拓扑作为 attention mask）

  思路：Decoder 的 face_attn2
  现在对所有面平等对待。如果我们在推理时把预测出来的邻接关系作为 attention bias
  注入 face_attn2，相邻面会更多交换信息，decode 出来的几何更一致。

  def decode(self, encoding_result, v_data=None):
      face_z = encoding_result["face_z"]

      # ─── 先预测拓扑 ───
      if v_data is None:  # 推理模式
          # 先粗略预测哪些面相邻
          indexes = all_pairs(face_z.shape[0])
          feature_pair = face_z[indexes]
          raw_pred = self.classifier(self.inter(feature_pair))
          adj_prob = torch.sigmoid(raw_pred).reshape(num_faces, num_faces)

          # 用预测的拓扑作为 face_attn2 的 attention bias
          topo_bias = torch.log(adj_prob + 1e-6) - torch.log(1 - adj_prob +
  1e-6)
          attn_mask = -topo_bias * 2.0  # 转为 additive mask (PyTorch 
  convention: 负=屏蔽)
      else:
          attn_mask = v_data["attn_mask"]  # 训练时用 GT mask

      # ─── Topology-aware decoder ───
      face_feature = self.face_attn_proj_in2(face_z)
      face_feature = self.face_attn2(face_feature, src_mask=attn_mask)  # ← 
  拓扑引导！
      face_z = self.face_attn_proj_out2(face_feature)

      # ... 后续 decode 不变 ...

  改动量：~15行代码。不改网络结构，只改推理时的 attention mask 计算方式。

  注意：训练时 v_data["attn_mask"] 是基于 GT batch 结构的 padding mask，不是拓扑
   mask。你可以在训练时也用 GT 拓扑作为
  bias（让模型学会利用它），推理时用预测的。

  ---
  改法3：边约束面的 decode（Edge-Conditioned Face Refinement）

  思路：先 decode 边 → 用边的几何信息 refine 面的 decode。因为边定义了面的边界，
  如果面知道自己的边长什么样，它可以更好地重建边界区域。

  def decode(self, encoding_result, v_data=None):
      face_z = encoding_result["face_z"]

      # Step 1: 预测拓扑 + decode 边（和现在一样）
      ...
      edge_feature = self.inter(face_pairs)
      edge_points = self.edge_points_decoder(edge_feature)  # [E, 16, 6]

      # Step 2: 把边的信息聚合回面 (NEW)
      # 每个面收集它所有边的特征
      edge_info_per_face = scatter_mean(
          edge_feature,
          edge_face_connectivity[:, 1:].flatten(),  # 每条边属于两个面
          dim=0,
          dim_size=num_faces
      )  # [N, edge_feature_dim]

      # Step 3: 用边信息 refine 面特征，再 decode
      face_z_refined = face_z + self.edge_to_face_proj(edge_info_per_face)
      face_points = self.face_points_decoder(face_z_refined)  # ← 
  现在知道自己的边了！

  改动量：中等（加一个投影层 + scatter 操作）。需要重训 VAE。

  好处：面在 decode 时"看到"了自己边界的约束，更容易生成一致的边界点。

  ---

  Column 1: 拓扑信息来源
  Encoder: GT 边结构（GAT 沿真实边传递）
  Decoder: AttnIntersection 预测
  ────────────────────────────────────────
  Column 1: 拓扑如何影响几何
  Encoder: 直接影响 — GAT 改变了 face_feature
  Decoder: 不影响 — 预测完就结束了
  ────────────────────────────────────────
  Column 1: 结果
  Encoder: face_z 自然包含拓扑一致性
  Decoder: 解码出的面/边几何不一致

  ---

  让预测出来的拓扑关系反过来约束几何解码。

  现在: predict topology → output
  改后: predict topology → 用它约束几何 → output

  具体:
    Step 1: 先预测拓扑 (哪些面相邻)
    Step 2: 用拓扑结果指导面的decode (相邻面互相对齐)
    Step 3: 用拓扑结果指导边的decode (边必须在相邻面的边界上)
